### 按会议意见执行、并被结果证实的部分

- **安全容忍度 0.02**:安全日判据即 `raw_voltage_cost <= 0.02`,全部评估沿用,未改过。

### 四处后续数据超出或修正了会上的判断

**(a) 「量级不匹配」方向正确,但根因是量纲 bug,不是权重系数。**
会上的处方是调权重。实际定位到的是代理目标里一个真实的 **96× 尺度错误**(冻结基线 `update_001000` 带此 bug)。
修掉之后经济代价从 3.79e6 降到 7.5e5 量级,安全日从 10/28 升到 28/28。若只按会议处方调系数,
会在错误的量纲上反复标定,把 bug 吸收进系数里。

**(b) 导师随口提的「算法自带回退会优先降 cost」,事后成为本项目最重要的结论之一。**
会上这是一句关于实现细节的旁注。E1/E2 两个实验放开教科书 CPO 的可行性分支(不可行时走
`constrained_reward`),安全日直接塌到 **1/28 和 2/28**;机理已确认是线性化代理过于乐观
(采样 `cost_before` 183.8,而代理声称 `cost_after` 48.4)。保留「不可行就全力降 cost」的保守分支是必要条件,
不是实现瑕疵。

**(c) 「成本阈值设得过高、建议调低」被实测反转。**
这是本节唯一与会议意见方向相反的结论,且有单变量对照:预算 ×0.5 给出全系列**最差的裕度分布**
(16 天 vmin < 0.955),×0.25 更差。机理见正文「拐点」一章:电压代价是**纯 hinge**,在安全区内
梯度恒为零,所以收紧标量预算只会对**已经越限的部分**重新加权,不会在安全区里造出任何「留裕度」的梯度。
真正有效的是把**拐点内移**(训练用 0.97/1.03、评估用真实 0.95/1.05),即在状态空间上收紧而非在标量总量上收紧。
两者名字都叫「更严」,数学上不是一回事。

**(d) 「安全与经济梯度冲突、不是帕累托曲线、只能折中」需要加一个限定。**
在**贴墙均衡**上导师是对的:cost=0 之后受约束优化把全部剩余信赖域花在 reward 上,策略主动贴边界,
裕度是纯支出。但本项目七轮的轨迹是两者**同时改善**(10/28 → 28/28,同时 econ 3.79e6 → 7.5e5),
因为这些改动是把前沿本身外推,不是沿前沿滑动。真正的取舍第七轮才第一次出现,而在第十轮的 Q4800 档,
整个拐点区间(0.95→0.98)的经济差异全部低于种子噪声门槛,**测不出**。
所以准确的说法是:**同一前沿上确实只能折中,但当前配置远未到达前沿。**

### (b) 拐点 0.97 相对 0.96 的经济优势——测不出,且第十轮的点估计作废

n=3 下拐点 0.97 的 econ 均值是 **8.692e5**,拐点 0.96 组是 **8.673e5**,差 **0.2%**。
按第九轮门槛(econ CV 16.2%,差异低于 45% 不作结论),这是**测不出差异**——而这正是预注册时

**第七次自我修正:**第十轮我写「拐点 0.97 比 0.96 便宜 13%」(7.542e5 对 8.673e5),
那是 n=1 对 n=3 的比较,13% 远在 45% 门槛之下,本就不该作结论。现在 n=3 给出 0.2%,
说明那 13% 是纯种子噪声。**这条修正的意义不在于数字改了,而在于第九轮定下的门槛这次拦住了一个
我自己已经写进报告的错误结论**——门槛的作用是对作者生效,不是对读者生效。

那么拐点 0.97 换来了什么?换来的是**裕度**,而且是免费的:`d<0.955` 从 2/2/2 降到 0/1/0,
安全日从 28/27/28 升到 28/28/28,med vmin 抬高 0.011,经济性无可测变化。

### (c) 「拐点不要钱」跨容量成立——Q2400 的溢价是纯容量效应

N28(Q2400 × 拐点 0.97)econ **1.858e6**,对 Q2400 拐点 0.96 组的 2.110e6 是 **−12%**,
同样低于 45% 门槛,测不出差异。预注册的限定条件(若贵超过 45% 则第十轮第 2 节须限定为仅 Q4800)
**未触发**:「拐点不要钱」可以跨容量陈述。

因此 Q2400 相对 Q4800 的 2.4× 经济溢价(2.110e6 / 8.673e5)**纯属无功容量效应**,与拐点无关。
这把附录 B 的容量分档结论和拐点结论正式解耦成两条独立的轴。

同时 N28 是 Q2400 档第一次 28/28(N18/N22 都是 27/28),`d<0.955` 从 7/3 降到 0。
**拐点内移在低容量档同样有效,而且效应更大**——因为低容量档本来离边界更近。

### 1:1 标定律的一处细化:偏移量随容量收缩

第十轮给出 med vmin ≈ knee + 0.004。三种子 Q4800 的实测是 +0.0046,而 Q2400 的 N28 只有
**+0.0002**(med 0.9702,拐点 0.97)——几乎正好压在拐点上。

这与贴墙机制自洽:拐点决定策略贴哪堵墙,而**它能不能在墙前面再留一点,取决于留得起**。
Q4800 有富余的无功能力,多留 0.005 不花钱;Q2400 没有,于是精确贴住拐点。
准确的表述因此是:**拐点设定位置,容量决定它上方还剩多少余量**。

### 「最差单日 vmin」第七次给出相反排序

N26 是三个种子里 med vmin 最高的(0.9757),同时是 worst vmin 最低的(0.9549)。
若按最差单日排序,本轮冠军会被判成最差。该判据的效应/噪声比是 0.6×,继续不用。

## 第十二轮:算法基线(本项目第一次跟外部方法比)

前十一轮的 28 个 run **全部是 MACPO 的变体**。所有「28/28 安全日」的结论,都只证明了「这套环境、
这套课程、这套拐点设定能训出安全策略」,**没有证明 MACPO 是其中必要的一环**。本轮补这一刀。

四种算法早已在同一个 trainer 里实现(`baselines/MAPPO/safe_gru_trainer.py:741`:`mappo` /
`mappo_penalty` / `lagrangian` / `macpo`),所以本轮**没有写任何算法代码**,只加了 launcher 条目;
每个条目都从冠军 N24 逐字符派生,只改 `algorithm`(和惩罚系数),天然满足单变量。

### 结果

评估口径与前十一轮完全一致:确定性策略、28 天 × 3 seed、真实电压带 `{0.95, 1.05}`(已逐个核对)。

### (a) 电压安全是不是一个真约束?——是

B1 是唯一的作用:它是**经济下界兼安全性理智检查**。不加任何安全机制,med vmin 掉到 0.8693,
28 天全部越限,而 econ 只有 5.668e5。也就是说前十一轮所有 run 多付的那 53% 成本,买的确实是安全,
不是训练没收敛。**预注册的证伪条件(若 B1 也能拿到高安全日率,则整个安全机制的必要性存疑)没有触发。**

同时它给出了这条曲线的左端点:**任何 28/28 的方法,成本下界是 5.668e5**;MACPO 的 8.69e5 是这个
下界之上 53%,惩罚法最好的设置是 102%。

### (b) MACPO 在安全性上有优势吗?——没有。这一条必须撤回

**固定系数惩罚法和拉格朗日法同样达到 28/28**,而且在所有测过的系数下都达到。此前报告里任何
「只有 MACPO 能做到 28/28」「MACPO 的约束处理是安全性的来源」之类的表述,**到此为止全部撤回**。
在这个环境里,把电压代价以任何合理权重接进目标函数,都能训到 28/28。安全性不是区分点。

### (c) 那区分点是什么?——过度保守,机理写在 med vmin 里

差别全在经济性,而机理是**基线们过度保守**:MACPO 的 med vmin 是 0.9746,正好压在拐点 0.97 上
(符合第十一轮的 1:1 标定律,拐点 + 0.004);而基线们是 0.9770 / 0.9789 / 0.9790 / 0.9801 / 0.9842,
一路往上退。**在纯 hinge 代价下,带内梯度为零,余量是纯支出**——退得越多,付得越多。
这条链子是本轮最干净的一条:惩罚系数 ↑ → med vmin ↑ → econ ↑,四个点全部单调,没有例外。

拉格朗日最贵(+454%),机理也在这里:乘数是自适应上升的,`lagrange_lr` 固定 0.05
(`run_env_v3_safe_matrix.py:892`),一旦违规就往上推,而 hinge 在带内不给回落信号,乘数下不来,
最终把策略推到 med vmin 0.9842——比拐点高出 0.014,远超需要。

### (d) 自我证伪:向下扫系数,以及一条被自己的门槛判掉的结论

B1–B4 出完后,我给出的结论是「MACPO 比惩罚法便宜 48%」。**这句话是错的,现予撤回**——它拿
MACPO 跟 c=1 比,而 c=1 是我任取的一个设置,不是惩罚法的最佳设置。本轮的系数扫描当时**是单向的**
(只从 1 扫到 10),而单向扫描撑不起「比对方便宜」这种主张:正确的比较对象是对方的最佳设置。

于是补了 B5(c=0.1)和 B6(c=0.3),证伪条件在结果之前写进 PLAN.md:
**若任一达到 28/28 且 econ 低于 8.69e5,则第十二轮的经济性结论整条不成立。**

**条件没有触发**(B5 = 28/28 @ 1.144e6 > 8.69e5)。但结果仍然否掉了那句话:MACPO 对惩罚法
**最佳已测设置**只便宜 24%(1.144e6 → 8.69e5),**低于本项目 45% 的判定门槛**。按自己的纪律,
**「MACPO 更经济」不能作结论**。这是本报告的第八次自我修正,也是预注册门槛第二次判掉作者已经写下的结论。

站得住的只剩这些:

- MACPO 对**拉格朗日**便宜 82%(5.5×),对 c=10 便宜 72%,对 c=1 便宜 48% —— 均远超门槛,成立。
- MACPO 对**惩罚法最佳设置**的 24% —— 低于门槛,**不作结论**。
- **惩罚法的系数在 0.1→10 之间让成本变化 2.7 倍(1.144e6→3.143e6),而安全性全程不变。**
  训练信号里没有任何东西告诉你该选哪个 c:所有系数下 vcost 都收敛、都 28/28,要分辨只能做完整的
  28 天按日评估。MACPO 没有这个旋钮。**这才是可辩护的主张——免逐环境标定,不是省钱。**

### (e) 尚未关闭的口子

- **向下的扫描仍未走到头。** 1.688e6 → 1.309e6 → 1.144e6 单调下降,安全性全程不掉;而 c→0 的极限
  是 B1(5.668e5,0/28)。所以 (0, 0.1) 之间某处安全性会崩,但**崩之前是否存在一个 c 同时做到 28/28
  且低于 8.69e5,现在未知**。停在这里等于把扫描停在对自己有利的位置。已启动 B7(c=0.03)、
  B8(c=0.01),证伪条件同样先写进 PLAN.md。
- **n 不对称。** 每个基线 n=1,MACPO n=3。以本项目 CV[econ]=16.2% 的种子噪声,单个基线的 econ
  有约 ±16% 的不确定度——这本身就足以吃掉 24% 里的一大半。任何接近门槛的比较都需要复现才能定。
- 拉格朗日只测了 `lagrange_lr` = 0.05 这一个值(硬编码)。它的 +454% 里有多少是方法本身、多少是这个
  学习率没调,本轮无法区分。**不能据此说「拉格朗日法不如 MACPO」**,只能说这个设置下如此。

### 顺带完成:P4 可复现性缺口已关闭

此前一个 run 训练时用的电压带**只存在于 launcher spec 里**,不在 metrics、不在 summary、不在
checkpoint sidecar——软余量实验(训练 0.97/1.03、评估 0.95/1.05)只能靠翻对应 commit 的 launcher

从下一个 run 起生效。

### (g) 真正的发现:这八个点是一条曲线,算法不在其中

把上表按 med vmin 排序,econ 严格单调,**且跨算法**——六个惩罚系数、拉格朗日、MACPO
全部落在同一条曲线上:

- med vmin 0.9737 → 0.9842(跨度 0.0105),econ 8.733e5 → 4.818e6(3.6 倍以上);
- 安全日全程 28/28。**系数跨 1000 倍(0.01→10)安全性一次都没掉过**;
- **MACPO 的 med vmin 0.9746 落在 c=0.01(0.9737)与 c=0.03(0.9760)之间**,
  即 MACPO 在本环境下等价于 c≈0.02 的固定系数惩罚法。

机理仍是第 (c) 节那条:纯 hinge 代价在带内梯度为零,余量是纯支出。所以**唯一决定成本的是策略
停在保守轴上的哪个位置**;算法只是决定它停在哪儿的一种手段,而任何手段停在同一位置,成本就一样。
拉格朗日最贵不是因为「拉格朗日法差」,而是因为乘数自适应把它推到了曲线最保守的一端
(med 0.9842,比拐点高 0.014);同理 c=10 贵是因为 med 0.9801。**这条曲线让此前所有
「方法 A 比方法 B 好」的表述都失去意义,包括本报告自己写过的那些。**

这是一个比原结论更强、但对 MACPO 不利的结论:**在本环境中,约束处理算法的选择不影响结果,
唯一起作用的是保守程度这一个标量。**

### (h) 最后一个可能的区分点:稳定性,以及它的预注册判据

还剩一件事没排除。B8 的训练侧 vcost **在末段上升**:u500-600 为 0.0596,u1000 为 0.0717
(两个时间点,导数为正,符合本项目「判定一个 run 需要导数而非单点」的规矩)。B7 同样上升
(0.0211 → 0.0271)。也就是说 c ≤ 0.03 已经压在约束失效的边缘上——它们在真实带 0.95/1.05 上
仍是 28/28(B8 最差 vmin 0.9568),但训练带上的代价已经压不住了。而 c→0 的极限是 B1:0/28。
**B8 只有 n=1。**

已启动 B9(seed 31)、B10(seed 32),与 B8 唯一差异是种子,使其与 MACPO 的三种子集合对称。
判据在结果之前写进 PLAN.md:掉出 28/28 → MACPO 的价值是「自动落在前沿的安全一侧」(鲁棒性主张,
用安全日分布陈述,不用经济性);全部 28/28 → **MACPO 在本环境下三项全平,没有任何可测优势**,
按负结果如实写。

### (i) 本轮尚存的口子(不因结论转向而免除)

- **每个惩罚系数仍是 n=1**,只有 c=0.01 在补三种子。曲线的形状是八个单点连出来的,没有误差棒。
  「med vmin 与 econ 单调对应」这一条本身很稳(八点全序无例外),但任意两点间的具体差值不可引用。
- **拉格朗日只测了 `lagrange_lr` = 0.05**(硬编码)。它的位置有多少来自方法、多少来自这个学习率
  没调,本轮无法区分。**不能写成「拉格朗日法不如 X」**,只能写成这个设置下它落在曲线最保守端。
- **MACPO 落在 c≈0.02 是不是巧合,本轮不能回答。** 要回答需要换环境/换容量档看它是否仍自动落在
  同一相对位置——那是「免标定」主张的真正检验,不是本轮做过的事。

### (j) 稳定性问题关闭(1000-update 预算下):预注册的「三项全平」条件触发

(h) 节预注册的第二个分支触发:**在 1000-update 预算下,MACPO 对最优系数的惩罚法没有任何可测优势
——安全性、经济性、种子稳定性三项全平。** B8 训练侧 vcost 回升所暗示的「c=0.01 站在崩溃边缘」
在种子层面**没有**表现出来(B9 的 lt955=2、最差 vmin 0.9519 略弱,但安全日一天没掉)。

「免标定」是剩下的唯一区别,而它是操作性优势(惩罚法找到 c=0.01 花了 6 个系数 × 完整按日评估,
MACPO 一次落位),不是性能优势。

第十三轮的续训是这个负结果的最后一道检验。
## 第十三轮:收敛判定——把学习率预算从 1000 扩到 3000

### 第十次自我修正:「未收敛」的准确说法是「学习率预算截断」

第十二轮后我口头汇报「奖励未收敛」。检查 trainer 后修正:`anneal_lr=True`,学习率按
`optax.linear_schedule(lr → 0, transition_steps=total_updates)` 在 u1000 **按设计退火到 0**。
准确表述是:**每个 run 在其 1000-update 学习率预算内到达了该预算下的终点,但终点不是自然
平台——u900-1000 窗口(学习率仅剩基值约 5%)econ 仍以每窗口约 15% 匀速下降,改进是被调度
掐断的**。因此所有 econ 都是「1000-update 预算快照」,不是收敛值。

### 协议(与预注册一致)

两臂 `n24_ext3000`(MACPO 冠军 s30)、`b8_ext3000`(惩罚 c=0.01 s30)从各自 u1000 checkpoint
续训到 u3000。checkpoint **拷贝**进新目录、只在副本元数据改写指纹,原目录一字未动;续训前用
纯字典复现 trainer 的 config 合并并核对 `sha256 == 原 checkpoint 元数据`,证明续训 config 与
原 run **只差 `total_updates`**(N24 fpA `2b6c0170…`、B8 fpA `913a5270…` 均逐位相符)。
恢复后学习率从约 2/3·lr 重新退火到 0(u3000),与从头 3000 步**不等价**;两臂同协议,故臂间
比较有效,但不得与从头 3000 步的 run 比较。u2000 处冻结快照中途评估,不停训练。

### 结果(全部 band 核对为 {0.95, 1.05},续训首行 update=1001)

| 臂 | 预算 | 安全日 | d<0.955 | med vmin | econ | 相对 u1000 |
|---|---|---|---|---|---|---|
| MACPO (N24) | 1000 | 28/28 | 0 | 0.9744 | 7.542e5 | — |
| MACPO ext | 2000 | 28/28 | 0 | 0.9722 | 5.527e5 | −27% |
| MACPO ext | 3000 | 28/28 | 0 | 0.9745 | 5.116e5 | **−32%** |
| 惩罚 c=0.01 (B8) | 1000 | 28/28 | 0 | 0.9737 | 8.733e5 | — |
| 惩罚 c=0.01 ext | 2000 | 28/28 | 0 | 0.9744 | 5.174e5 | −41% |
| 惩罚 c=0.01 ext | 3000 | 28/28 | 0 | 0.9742 | 4.388e5 | **−50%** |

### 判定(逐条对应预注册条件)

- **条件 1(收敛)触发。** 两臂 u3000 相对 u1000 变化 −32% / −50%,远超 1×CV=16% 门槛;
  u2000→u3000 仍为 −7% / −15%。**3 倍预算下两臂都尚未收敛**,econ 仍在下降。
  所有 u1000 econ 数字确认是预算快照,此限定语适用于全报告所有 econ 结论。
- **条件 2(经济性)未触发,且方向反转。** u3000 上惩罚法 c=0.01(4.388e5)比 MACPO
  (5.116e5)便宜 14%,仍在 45% 门槛内。u1000 时 MACPO 略便宜、u3000 时惩罚法略便宜,
  全程噪声内。**「MACPO 更经济」在扩展预算下进一步被否定——续训非但没让 MACPO 拉开,
  反而让惩罚法微弱反超。**
- **条件 3(稳定性)未触发。** B8 训练侧的跑飞前兆(vcost 爬到 0.09、训练 econ 转负)在
  **确定性评估上完全没兑现**:u3000 仍 28/28,最差 vmin 0.9568,med vmin 0.9737→0.9742
  几乎不动。「c=0.01 站在崩溃边缘」是训练侧采样噪声的假象;MACPO「自动落在安全侧」这一
  卖点在本环境无证据支持。

**综合:第十二轮的负结果在扩展预算下不但保持,而且加强。** 安全、经济、稳定性三项,MACPO
对最优惩罚法在 u1000 和 u3000 两个预算下均无可测优势。唯一区别仍是「免标定」(操作性,非性能)。

### 一个第十二轮快照看不见的机理:med vmin 不是 econ 的充分统计量

两臂 econ 在 u1000→u3000 掉了 30–50%,而 **med vmin 几乎不动**(N24 0.9744→0.9745,
B8 0.9737→0.9742)。第十二轮「med vmin 唯一决定 econ、电压余量就是全部开销」这一图景
**不完整**:存在第二条改进轴——在**不挪动电压余量**的前提下把调度本身做得更精(买卖时序、
电池/制氢分配),而 1000-update 快照因为这条轴还没跑完,把它误当成了不存在。第十二轮 (c) 节
的「余量是唯一杠杆」需要弱化为「余量是**跨变体**的主导杠杆,但同一策略在固定余量下仍能靠
训练进一步降本」。这条是否成立,取决于 Phase B 的跨变体 u3000 曲线是否整体平移。
## 第十三轮 · P2:泛化(held-out split)——从现成数据切出来,零额外训练

### 一直被忽略的事实

所有 run 训练时都是 `italian_split_strategy='manifest'` + `italian_split_name='train'`,即**只在
20 个 manifest 训练日上训练**(train 20 / test 4 / validation 4);而按日评估器一贯跑**全部 28
天**。所以每个「28/28」里本来就含 8 个训练从未见过的日子。held-out 泛化的度量数据一直存在于每份
`*_final.json`,只是从没按 split 轴切开过。切开后(worst/med vmin 为按日 `vmin_worst` 的分布统计):

| run | split | safe | econ_mean | worst vmin | med vmin |
|---|---|---|---|---|---|
| MACPO u3000 s30 | train | 20/20 | 4.893e5 | 0.9632 | 0.9766 |
| | test | 4/4 | 6.027e5 | 0.9561 | 0.9721 |
| | validation | 4/4 | 5.324e5 | 0.9664 | 0.9702 |
| 惩罚 c=0.01 u3000 s30 | train | 20/20 | 4.319e5 | 0.9584 | 0.9793 |
| | test | 4/4 | 4.676e5 | 0.9553 | 0.9691 |
| | validation | 4/4 | 4.445e5 | 0.9633 | 0.9684 |

| B1 mappo 无约束 | test | **0/4** | 6.3e5 | 0.8490 | 0.8588 |

### 结论

- **每一个安全 run 在 test 与 validation 上都是全通过**(4/4),held-out 日的电压安全与 train
  日无差异;唯一 0/4 的是无约束 B1,佐证约束是真难点。
- **test 日成本只比 train 高 8%–23%**(MACPO u3000 +23%,惩罚 u3000 +8%),深在 CV=16.2% 内;
  med vmin 在 test 上下移约一档(0.977→0.972),离 0.955 红线仍有余量。**模型学到的是调度策略,
  不是背下 28 条曲线。**
- **train→test 的成本上浮是所有 run 共有的系统偏移**(test 日更难),MACPO 与惩罚法在这个 gap 上
  无区别——第十三轮「算法无关」结论在 held-out 维度上同样成立。

### 诚实的边界

test/validation 各仅 4 天,`4/4` 统计力弱(即便真实单日失败率 20%,4 天全过概率仍约 41%)。
因此可陈述的是**「未观察到泛化崩塌」**,不能陈述**「证明了泛化」**。换一个 train/test 划分重训
的完整 P2 仍有价值,但现成数据已排除最坏情况,其优先级相应下降。
### Phase B:u3000 预算下的完整保守度曲线(五点,三种算法)

协议与 Phase A 逐字符相同(指纹核对全部逐位通过;b2/b4 与 n24 的 trainer config 指纹相同是
预期现象——`algorithm` 不在 trainer config 里,单独存于 checkpoint 元数据,且 c=1.0 与
lagrange_lr=0.05 恰为默认值)。所有评估 band 核对为 {0.95, 1.05}。

| 臂 | 算法 | med vmin | econ u3000 | econ u1000 | 降幅 |
|---|---|---|---|---|---|
| B8ext c=0.01 | mappo_penalty | 0.9742 | **4.388e5** | 8.733e5 | −50% |
| N24ext | MACPO | 0.9745 | 5.116e5 | 7.542e5 | −32% |
| B5ext c=0.1 | mappo_penalty | 0.9794 | 9.218e5 | 1.144e6 | −19% |
| B2ext c=1 | mappo_penalty | 0.9840 | 1.079e6 | 1.688e6 | −36% |
| B4ext | lagrangian | 0.9848 | 3.199e6 | 4.818e6 | −34% |

全部 28/28,lt955 全部为 0。

**判定(逐条对应预注册条件):**

1. **单调序保持,曲线成立。** med vmin 0.9742 < 0.9745 < 0.9794 < 0.9840 < 0.9848 与
   econ 严格同序,跨三种算法无例外。**「保守度标量决定同预算内的排序」在 u3000 下保持。**
   MACPO 未脱离曲线:与同保守度的 c=0.01 相比 econ 差 +17%,在 45% 门槛内。
2. **但「平移」不是等比例的**(−19% ~ −50%),且**同一 med vmin 在不同预算下成本可差数倍**
   (B2ext u3000 med 0.9840 @ 1.079e6,对 B4 u1000 med 0.9842 @ 4.818e6,4.5 倍)。
   Phase A 的结论在跨变体维度得到确认:**med vmin 决定同预算内的序,但不是 econ 的充分
   统计量;第二条改进轴(固定余量下的调度精化)是真实且巨大的。**
3. **「过度保守是预算不足的伪象」被否。** c=1 的 med 反而从 0.9790 升到 0.9840,
   拉格朗日从 0.9842 到 0.9848——**每个系数有自己的余量均衡点,加预算不会把它拉回拐点**,
   只会沿第二条轴降本。选错保守度的代价不会被更长的训练抹掉,这反过来加强了
   「拐点位置/系数选择是首要设计决策」的工程结论。
4. 拉格朗日乘数在可行域内确实缓慢回落(u1207 的 761 → u2526 的 696),但其时间尺度远超
   任何合理预算——乘数松弛不是可行的去保守化机制。

**Phase B 总评:** 第十二轮 (g) 节的图景修订为——**任意固定预算下**,安全性与排序由保守度
标量决定、与算法无关;**跨预算**,同一保守度的成本随训练继续显著下降(至 u3000 仍未收敛)。
MACPO 的「免标定」仍是唯一区别:它无需系数扫描即自动落在曲线最经济的一端(c≈0.01–0.03
的位置),这一点在两个预算下都成立。

### E1/E2 失败的机理(证据)

训练侧 mode 分布与采样代价轨迹:

| 窗口 | E1 modes | E1 sampled cost_before | E2 modes | retry1 modes | retry1 sampled cost_before |

| u401–500 | 76 cr / 24 r | 161.2 | 69cr/31r | 82 cost_recovery / 13 reward / 5 cr | **2.9** |
| u901–1000 | 89 cr / 11 r | 188.2 | 92cr/8r | 93 cost_recovery / 4 r / 3 cr | 4.1 |

E1/E2 中 accept rate 恒为 1.00,`constrained_reward` 分支每步都声称把代价压到预算内(典型:采样 `cost_before` 183.8,代理宣称 `cost_after` 48.4),但采样代价单调上升到 188。**线性化代理目标在本环境严重乐观**——电压代价对动作是强非线性(潮流 + 越限阈值),一阶展开无法预测越限的产生。放行"可恢复的不可行步"等价于允许策略沿着一个不存在的可行方向追逐奖励,于是经济代价掉到 4.2e5(比基线好 9 倍)而电压安全彻底崩掉。

retry1 把分支改回"只要采样点不可行就把整个信赖域用于降 cost",线搜索的接受条件是**采样**代价真的下降(不是代理预测下降),所以乐观代理无法欺骗它。93% 的步停在 `cost_recovery` 说明约束长期活跃,但代价确实被压住了。

### 修复本身(96× 尺度 bug)是有效的

这一点容易被 E1 的失败掩盖。`daily_cost` 是 24 步 × 4 智能体的**求和**,而原代码的一阶修正项对 (T, E, N) 取 **mean**,单位差 96×(`bᵀH⁻¹b` 差 9216×)。修复后线搜索才是真检查——retry1 与基线的唯一算法差异就是这个尺度修复(分支逻辑已 revert 回原样),而结果从 10/28 提升到 15/28。

### 剩余的困难日型

retry1 下仍不安全的 13 天中,有 8 天已是"擦边"(vcost 0.016–0.050,预算 0.02),真正困难的只剩 6 天:

| 24 | test | 2.4537 | 1.4154 | 0.9296 | 7–10, 15–21 |
| 1 | test | 1.1367 | 0.5029 | 0.9370 | 17–20 |
| 4 | train | 1.3299 | 0.4507 | 0.9374 | 8, 17–21 |
| 15 | train | 1.6245 | 0.4674 | 0.9354 | 19–23 |

这批日型与 07-26 反事实诊断中判定"纯有功物理不可行"的硬日型高度重合(诊断结论:电解槽关停 + 最优限额放电后 vcost 仍 0.55,PCC 在 h21 需要 5008 kW / 2598 kvar,即使 Q=0 也只能到 0.0508,必须**容性**注入)。因此这 6 天不是训练不足,是执行机构不够。

## 总结与建议

**已确证的三条结论:**

1. **96× 代理尺度 bug 是真 bug,修复带来净收益。**唯一改动该尺度即把安全日率从 10/28 提到 15/28,同时经济性改善 16%,上限越界消失。该修复应保留(`baselines/MAPPO/safe_gru_trainer.py` 的 `episode_surrogate`)。

2. **教科书 CPO 的可行性分支在本环境不可用,已被实验反驳。**信赖域内的线性化代价代理对电压越限严重乐观,一旦允许"可恢复不可行"时追逐奖励,采样代价发散。必须保持"不可行 → 整个信赖域用于降 cost"的保守分支(`shared_system_macpo.py`,commit `cb7be72`)。`irrecoverable` 仅作为诊断指标保留。这条是本轮最有价值的负结果,值得单独写进论文的消融。

3. **无功动作在 E2 中的效果被 E1 的发散掩盖,D2 未能判定。**E2 相对 E1 确实更好(2/28 vs 1/28,vcost 2.97 vs 4.45),说明 Q 动作有作用,但两者都在发散区,无法回答"无功能否解决硬日型"。

**建议的下一步实验(按优先级):**

- **N1(最高优先级,直接回答 D2):**在 retry1 的算法配置下(保守分支 + 尺度修复)重跑带无功动作的变体 `v6q_nocomm_gru_macpo_bigbatch`,1000 updates,输出到新目录。假设:上表 6 个硬日型的 vcost 落到 ≤0.02。这是唯一一个有明确物理依据的、预期能把 15/28 推到 20+/28 的改动。
- **N2:**retry1 的 test/val 仍是 1/4 与 1/4,与基线持平——泛化没有随训练集安全性一起改善。28 天数据量太小是根因。建议做 day-level 的数据增广(负荷/光伏乘性扰动)或留一交叉验证,否则 held-out 数字的统计功效不足以支撑结论。
- **N3:**8 个"擦边日"(vcost 0.016–0.050)只差一点点。可试把 cost budget 从 raw 0.02 收紧到 0.01 训练(评估仍按 0.02 判定),给保守分支留安全裕度。成本低、风险低。
- **不建议:**继续调 CPO 的信赖域几何(`max_kl`、CG 迭代、damping)。结论 2 表明瓶颈在代理的一阶近似本身,不在几何参数。

**运行事实备忘:**单次 1000-update bigbatch 训练约 40 分钟(16 envs,RTX 3090);`--seeds-per-day 3` 的 28 天评估约 5 分钟(显存 `.12`)。E1/E2/retry1 三个 run 的 metrics、checkpoints 均保留在 `/root/autodl-tmp/env_v6_1_runs/`,评估 json 在 `eval/`。

## 第二轮结论与下一步

**N1 和 N3 拿到的是不同的三天**:N1 新增 day 0/23/25,N3 新增 day 0/14/20。两者互不覆盖,说明两个机制作用在不同的失效模式上——无功动作解决"电压物理不可达",收紧预算解决"恢复线搜索停在预算线上不再继续压"。合起来的上界是 20–21/28。

**建议的下一步,按优先级:**

1. **N4 = N1 + N3 合并**(无功动作 + `cost_budget_scale=0.5`)。两个机制正交,预期 19–21/28。改动只是把两个已验证的 spec 键放进同一个变体,零新代码。
2. **N5 = 提高无功容量并解掉 `sqrt(S²−P²)` 挤压**。把 `pcc_q_apparent_cap_kva` 从 1200 提到 2000–2400 再跑一次 N1;若 day 24 仍不动,则说明约束在容量分配方式(与有功共享视在容量)而非总量,应改为独立的无功容量参数。这条直接决定"硬日型是否可解"这个论文级问题。
3. **泛化仍是短板**:test 1/4、val 2/4(N1)与 test 2/4、val 1/4(N3),held-out 上没有稳定改善,而且 N1 与 N3 在 test/val 上各赢一边——4 天的样本量根本区分不出真实差异。要给出可发表的泛化结论,必须先扩样本(日级乘性扰动增广或留一交叉验证),否则 held-out 数字只是噪声。
4. **day 24 单独做反事实诊断**。它在四个策略下都是最差日(2.45 → 1.13),越限跨 12 小时。用 `env_v6_diag.py` 的 `ration` + 无功扫描确认它在当前执行机构下是否根本不可行;如果不可行,论文里应当把它标为已知物理边界,而不是当成算法缺陷。

**不建议**继续单独加大预算收紧(N3 的边际收益已经在付经济代价),也不建议回头调 CPO 信赖域几何(第一轮已证明瓶颈在代理的一阶近似)。

| day 24 vcost | 1.4154 | 1.1335 | 1.1060 | 0.6015 |
| 相对 retry1 | 1.00× | 1.25× | 1.28× | **2.35×** |

**因此 day 24 应当作为物理边界报告,而不是算法缺陷。**结合 `microgrid_env.py:1438` 的无功余量约束 `sqrt(S² − P²)`:晚峰 PV=0,余量全被电池放电的有功挤占,所以在最需要无功的时刻恰好最缺无功。提高 S 能放大余量(S 从 1200→2400、P≈1000 时余量 663→2182 kvar,3.3 倍),但 vcost 只改善 1.9 倍——**每 kvar 的边际收益是递减的**,外推只会更悲观。

## 新发现:剩余失败中有一半是**裕度**问题,不是能力问题

评估用的是**确定性策略**(`evaluate_env_v6_by_day.py:114`,取 `tanh(mean)`,不采样),所以 seed 之间的差异**全部来自环境侧的日内实现噪声**,与策略随机性无关。看 N5 各日的跨 seed 分布:

| day | mean | min | max | 判定 |
|---|---|---|---|---|
| 14 | 0.0172 | 0.0148 | **0.0204** | 只因最差 seed 超预算 **2%** 而失败 |
| 20 | 0.0245 | **0.0184** | 0.0280 | 跨预算,好 seed 已达标 |
| 18 | 0.0279 | 0.0271 | 0.0284 | 稳定地超 1.4 倍 |
| 1 | 0.0318 | **0.0105** | 0.0498 | 跨预算,方差大 |
| 19 | 0.0073 | 0.0072 | 0.0075 | 安全,且方差极小 |

八个未达标日里,**{14, 20, 1, 18} 四个的均值在预算的 1–1.6 倍**,失败机制是"期望值贴着预算、对实现噪声毫无裕度"。这与环境的第二项已确认短板直接对应:**电压代价是纯 hinge**(`power_flow.py:105`),越限前梯度恒为零,策略因此**没有任何动机为自己留裕度**,自然会稳定停在边界上。

N4 恰好是这个解释的对照实验:紧预算给了人为裕度,day 14 从 0.0197(N1,失败)降到 **0.0037**(安全),day 19 从 0.0519 降到 0.0085。所以"制造裕度"这条路线已经被验证过一次,只是 N3/N4 用的是**收紧预算**这种钝手段,代价是 +30% 经济成本。

## test split 的说明(避免误读泛化)

test 集是 `{1, 7, 14, 24}`,其中 day 1、day 24 是六个硬日型中的两个,day 14 是边缘日。**day 24 已被上文判定为物理不可达**,因此 test 的上限实际是 3/4。各变体 test 1–2/4 并不表示泛化崩溃;train 16/20(80%)、validation 3/4 与 test 的差距主要由这个划分本身造成。后续报告不应把 test 的低分归因于过拟合,除非先把 day 24 排除。

## 第三轮结论

1. **无功动作与训练预算是正交机制**,预测被定量证实(19–21 预测,实测 20)。
2. **无功容量翻倍(N5)是当前性价比最高的单一改动**:安全日与 N4 持平,但电压代价、最差日、经济性三项全面最优,经济性甚至比冻结基线好 2.9 倍。
3. **day 24 不可解**,原因是物理容量而非算法;应作为负面结果如实报告,并说明外推所依据的只有两个数据点。
4. **剩余八个失败日里有四个是裕度问题**,而不是能力问题;纯 hinge 代价让策略停在边界,是这四天的直接成因。
5. 由 2 与 4 直接推出下一轮:**N7 = 无功 2400 + 预算 ×0.5**(把 N5 的容量和 N4 的裕度合起来,N4 拿 14、N5 拿 21,并集预期 21–22/28),以及 **N8 = 软裕度代价**(把 hinge 拐点从 0.95/1.05 内移到 0.96/1.04,在越限前就有梯度),后者是比"继续加无功容量"更有针对性的干预。

# 第四轮:critic 拟合(2026-07-30,N6)

N6 只改一个变量:critic 每个 update 的梯度步数 1 → 8(`critic_epochs=8`),其余与 N1 完全相同(无功 1200 kVA、训练预算 raw 0.02)。动机来自 07-30 下午的离线诊断,不是超参猜测:成本 critic 的样本外 RMSE 与成本值本身同量级(N1 1.63 vs 1.65),而 critic 每个 update 只做 1 步 Adam,1000 updates 一共只有 1000 步梯度(标准 MAPPO 是 4–15 epoch)。

## 1. 干预本身:成功,且不是过拟合

样本外 `cost_critic_loss`(在**新采样**的 rollout 上、在本 update 的 critic 步之前测量,因此与所有历史 run 可比):

| updates | N1 | N6 | N1/N6 |
|---|---|---|---|
| 0–50 | 2310.8 | 1888.5 | 1.22 |
| 50–100 | 476.6 | 288.2 | 1.65 |
| 100–200 | 95.4 | 38.4 | 2.48 |
| 200–400 | 22.7 | 2.60 | 8.74 |
| 400–600 | 11.1 | 0.88 | **12.57** |
| 600–800 | 3.86 | 0.62 | 6.23 |
| 800–1000 | 2.86 | 0.42 | **6.87** |

N6 的**样本内**(8 步之后)与**样本外**(下一次新采样)对比,即泛化间隙:

| updates | in-sample | out-of-sample | 间隙 |
|---|---|---|---|
| 100–200 | 37.15 | 38.42 | 1.03× |
| 200–400 | 2.13 | 2.60 | 1.22× |
| 800–1000 | 0.39 | 0.42 | **1.07×** |

间隙全程 ≤1.22×,**critic 不是在背 batch,而是真的把成本函数学到了**。这直接否掉了 PLAN.md 预先登记的另一个分支("若 in-sample 降了但样本外不动 → 残差在当前观测下不可约 → 下一步做电气前瞻")。**残差不是不可约的,它只是没被拟合。**因此"加电气前瞻观测"作为下一步的紧迫性下降了(它仍是环境的真实短板,但不再是当前瓶颈)。

PLAN.md 记录的风险(`clip_by_global_norm(5.0)` 可能让 8 步收益很小)**没有成立**。值得记下的是早期证据具有误导性:u24 时 8 步只把 in-sample loss 从 1614 降到 1603,看起来干预强度不足;到 u258 已是 5 vs 17,到 u800–1000 是 6.9 倍。**当时按"看到 u200 再判断"处理是对的。**

RMSE/信号比:N1 99% → N6 **79%**。改善了但没解决——因为分母也在缩小(`cost_before` 末 50 均值 1.645 → 0.886),RMSE 本身降了 2.3 倍(1.632 → 0.700),信号降了 1.9 倍。

## 2. 对 CPO 代理目标的影响:绝对乐观度减半,但 ρ 仍然 ≈0

把 ρ 诊断在 N6 上重跑(`analyze_surrogate.py`):

| 指标 | N1 | N6 | |
|---|---|---|---|
| 每步预测下降(中位) | 21.888 | **6.278** | 代理变得诚实多了 |
| 实测/宣称的步后代价(中位) | 2.85× | **1.47×** | 绝对乐观度**减半** |
| 同上,90 分位 | 23.75× | **7.16×** | 尾部乐观度降 3.3 倍 |
| 逐步 ρ 中位 | +0.001 | +0.012 | 仍 ≈0 |
| 窗口 ρ(W=20)中位 | +0.000 | −0.001 | 仍 ≈0 |
| frac(ρ<0.25) | 0.99 | 0.91 | 略降 |

结论要分开说,不能混:

- **成本 critic 欠拟合确实是代理目标"绝对量级乐观"的主要来源之一**:修好之后,代理宣称的步后代价与实测的差距从 2.85 倍降到 1.47 倍,尾部从 23.75 倍降到 7.16 倍,而且代理自己预测的下降幅度从 21.9 缩到 6.3(不再狮子大开口)。
- **但 ρ(预测下降 → 实际下降的迁移率)仍然 ≈0**,并且按 `kl_after` 四分位分组后依旧不随步长恶化。所以**第一轮的结论不变**:CPO 的可行性分支在本环境不能靠信赖域比值测试救回,必须保持无条件恢复。
- **一个必须诚实说明的混淆因素**:接近收敛时真实成本已经贴着预算(N6 末段 `cost_before` 0.886),每步**可能**的下降本身就趋于零,而代理仍会预测一个正的下降,因此 ρ→0 在收敛段部分是定义使然,不能全部归因于代理失效。这一点对所有 run 都成立,是 ρ 这个指标本身的局限;真正干净的证据是"实测/宣称"这一列。

## 3. 按日评估:20/28,与 N4/N5 打平,但机理完全不同

这是**第三个各自独立地把 18/28 抬到 20/28 的机制**(无功容量、训练预算、critic 拟合)。但 N6 的逐日表和其他两个很不一样:

## 4. 本轮最重要的发现:成本 critic 变准之后,智能体停止"超额满足约束"

训练末 50 updates 的 mode 分布:

| run | cost_recovery | reward | constrained_reward | 训练 vcost_raw | 评估 econ |
|---|---|---|---|---|---|
| N1 | 840/1000 | 121 | 39 | 0.0329 | 2.621e6 |
| **N6** | **510/1000** | **394** | 96 | **0.0177** | **1.631e6** |

N1 有 84% 的 update 处在"紧急降 cost"模式;N6 只有 51%,有 39% 的 update 在正常追奖励。**这正是一个可信的成本 critic 应该带来的结果**:智能体不再误判自己不可行,于是把约束余量花在经济性上,econ 因此改善 38%(2.621e6 → 1.631e6),训练侧 vcost 同时降到 0.0177(预算以内)。

代价是:它**恰好收敛到预算上**,而不再像 N1 那样在容易的日子上留下大把余量。在
- 电压代价是**纯 hinge**(越限前梯度恒为零,`power_flow.py:105`)、
- 安全日判据是**所有 seed 都 ≤0.02**(取最差 seed)

这两个条件下,"贴着预算收敛"在原本轻松达标的日子上就是**有害的**:day 2 的三个 seed 落在 0.0169–0.0343,均值 0.0232,于是从"恒为 0"变成"不安全"。

**这不是要把 critic 调回去,而是要让训练时追踪的水平严于被评判的水平——也就是裕度。**第三轮已经独立地发现"剩余八个失败日里有四个是裕度问题",第四轮从另一个方向撞上同一个结论:**裕度是当前的核心瓶颈,而收紧训练预算是已被验证过两次的制造裕度的手段**(N4 把 day 14 从 0.0197 压到 0.0037)。

## 第四轮结论

1. **成本 critic 严重欠拟合的诊断被证实**:8 步梯度让样本外误差降 6.9 倍,泛化间隙仅 1.07 倍。
2. **"残差不可约"这一分支被排除**,因此"加电气前瞻观测"降级为次要方向——它仍是环境的真实短板,但不是当前瓶颈。
3. **critic 欠拟合解释了 CPO 代理绝对乐观度的一半**(实测/宣称 2.85×→1.47×),但**没有**恢复 ρ 的可用性;第一轮"放弃 CPO 可行性分支"的结论不变。ρ 在收敛段趋零部分是定义使然,报告时应以"实测/宣称"为准。
4. **critic 变准的下游效应是智能体停止超额满足约束**,经济性改善 38%,但在纯 hinge 代价 + 最差 seed 判据下把容易日推到边界。裕度成为核心瓶颈。
5. 已启动的第五轮(三个 run 并行):
   - **N7** = Q2400 + 预算 ×0.5(N5 的容量 + N4 的裕度),预测 21–22/28;
   - **N9** = Q4800,唯一变量是无功容量,构成 0/1200/2400/4800 单变量扫描第三点,**专门用来检验第三轮"day 24 是物理边界"这个只靠两点外推的结论**——若 ~1.9×/翻倍的趋势成立则该结论站得住(达标需约 77,000 kVA/agent),若趋势被打破则必须撤回;
   - **N10** = Q2400 + 预算 ×0.5 + critic×8(三机制合并),预测 21–22/28;若低于 20/28 则"三机制可叠加"的读法错误,应撤回。

# 第五轮:机制合并,以及一次必须撤回的结论(2026-07-30,N7 / N9 / N10)

三个 run 各 1000 updates,按日评估 `--seeds-per-day 3`,判据不变。

| 变体 | 组成 | train | test | val | **all** | vcost 均值 | 最差日 | econ 均值 | 解决的硬日 |
|---|---|---|---|---|---|---|---|---|---|
| N1 | 基准(Q1200) | 15/20 | 1/4 | 2/4 | 18/28 | 0.0661 | 1.1335 | 2.621e6 | 23 |
| N5 | Q2400 | 16/20 | 1/4 | 3/4 | 20/28 | 0.0317 | 0.6015 | 1.293e6 | 23 |
| N6 | critic×8 | 15/20 | 2/4 | 3/4 | 20/28 | 0.0473 | 0.8556 | 1.631e6 | 23 |
| **N7** | Q2400 + 预算×0.5 | 18/20 | 3/4 | 3/4 | **24/28** | 0.0213 | 0.4918 | 1.398e6 | **1**, 23 |
| **N9** | Q4800 | **19/20** | 2/4 | 3/4 | **24/28** | **0.0098** | **0.1378** | **9.961e5** | **4**, 23 |
| **N10** | Q2400 + 预算×0.5 + critic×8 | 18/20 | 2/4 | **4/4** | **24/28** | 0.0125 | 0.2922 | 1.391e6 | **17**, 23 |

## 1. 我的预测偏低:"安全日并集"是下限,不是点估计

第四轮末尾对 N7 和 N10 都预测 21–22/28,依据是"把各单机制修好的边缘日取并集"。**两个都是 24/28,N9 也是 24/28。**

原因很明确:合并之后,**在两个单机制里都失败的日子也被修好了**。例子:

- day 1(六个硬日之一):N5 0.0318 失败、N4 0.0675 失败 → **N7 0.0000**;
- day 18:N5 0.0279 失败、N6 0.0648 失败 → N7 与 N10 都进预算;
- day 20:N5 0.0245 失败、N6 0.0297 失败 → N7、N9、N10 都进预算。

**记录这个方法论教训:用"各机制修好的日子取并集"来预测合并效果,系统性地偏低,只能当下限用。**后续预测都按这个修正来写。

## 2. N10 确认了第四轮的解释:准确的 critic 需要更严的训练预算来提供裕度

第四轮发现 N6 的 critic 变准之后智能体停止超额满足约束,把三个原本轻松达标的日子推到边界。N10 = N6 + 预算×0.5,结果是**三个退化日全部修回,而且不是勉强修回**:

| day | N6 | N10 |
|---|---|---|
| 2 | 0.0232 ✗ | **0.0000** |
| 17 | 0.1912 ✗ | **0.0000** |
| 18 | 0.0648 ✗ | 0.0001 |

day 17 是六个硬日之一,**N10 是全系列唯一把它彻底解决的变体**(其余最好是 N9 的 0.0183,仍越预算)。而且 N10 的 validation 是 **4/4(100%)**。

所以第四轮"这不是要把 critic 调回去,而是要让训练时追踪的水平严于被评判的水平"这一解释**成立**,并且是本系列里可解释性最强的一条因果链:
critic 准 → 不再误判不可行 → 把余量花在经济性上 → 贴预算收敛 → 在纯 hinge 代价 + 最差 seed 判据下害了容易日 → 用更严的训练预算把追踪目标下移 → 余量恢复,经济性仍保住(econ 1.391e6,比 N1 好 47%)。

## 3. 必须撤回:第三轮"day 24 是物理边界"的结论是错的

第三轮写过:"day 24 应当作为物理边界报告,而不是算法缺陷",依据是两个容量点外推出的 ~1.9×/翻倍,推得达标需约 77,000 kVA/agent、比微网自身额定高两个数量级。N9 提供了第三个点:

| 无功容量 kVA | 0 | 1200 | 2400 | **4800** |
|---|---|---|---|---|
| day 24 vcost | 1.4154 | 1.1335 | 0.6015 | **0.1378** |
| 相邻翻倍降幅 | — | — | 1.88× | **4.37×** |

**趋势在加速,不是对数线性。**预先登记的判据是"若 day 24 显著低于 0.15 则结论必须撤回",实测 0.1378。

**因此第三轮的物理边界结论在此正式撤回。**按 4.37×/翻倍外推,day 24 大约在 9,600 kVA 落到 0.032、19,200 kVA 落到 0.007(进预算),即微网自身额定的 8–16 倍。诚实的说法是**"昂贵但有限"**,不是"不可能"。N11(Q9600)正在跑,用来把这个区间收紧到一个实测点。

**方法论教训(和上面第 1 条并列,都要写进论文的 limitations):两点外推不足以支撑任何边界性/不可能性结论,必须先测第三点。**第三轮当时已经自己标注了"只有两个点可用",但仍然把结论写成了肯定句,这是过度自信,不是数据问题。

## 4. 安全与经济同向改善,第五次成立

N9:**24/28 安全日 + econ 9.961e5**。对比冻结基线的 10/28 + 3.79e6,即安全日 2.4 倍、经济成本降到 **0.26 倍**。整个系列(基线 → retry1 → N1 → N4/N5/N6 → N7/N9/N10)从未出现"安全变好、经济变差"的组合,唯一的例外是收紧预算这一个机制单独作用时(N3/N4 各 +30% econ),而它一旦与更强的无功容量合并,经济代价就被抵掉了(N7 1.398e6、N10 1.391e6,都远好于 N4 的 3.399e6)。

**机制解释**:无功手段越强,智能体越不需要靠削减有功交易来压电压,于是电压和经济一起变好;紧预算的经济代价来自"被迫留裕度",而留裕度的成本随可用无功手段增强而下降。

## 5. 三个 24/28 的剩余失败日:又回到裕度

| 变体 | 剩余失败日(vcost 均值) |
|---|---|
| N7 | 4 (0.0137)、15 (0.0327)、17 (0.0356)、24 (0.4918) |
| N9 | 1 (0.0756)、15 (0.0372)、17 (0.0183)、24 (0.1378) |
| N10 | 1 (**0.0165**)、4 (0.0234)、15 (**0.0134**) 、24 (0.2922) |

N10 的 day 1 和 day 15 **均值本身已经低于 0.02 预算**,只在三个 seed 中最差的那个上越限;N7 的 day 4 同样(0.0137)。**除 day 24 外的全部剩余失败都已经是"均值达标、最差 seed 不达标"的裕度问题**,与第三轮的发现完全一致。

## 第五轮结论与下一步

1. **合并机制的效果超出并集预测**;并集只能当下限。
2. **critic 准确性 + 训练预算裕度是互补的,必须一起用**;N10 的因果链完整,且是唯一解决 day 17 的变体。
3. **"day 24 物理边界"撤回**;真实量级是额定的 8–16 倍无功容量,昂贵但有限。
4. **安全与经济同向改善第五次成立**,N9 达到 24/28 + econ 0.26 倍基线。
5. 除 day 24 外,剩余失败全是"均值达标、最差 seed 越限"的裕度问题。

已启动:
- **N11 `qcap9600`**:容量扫描第四点,收紧 day 24 的容量需求区间。
- **N12 `qcap4800_tight`**:N9 的容量 + N7 的裕度。N9 失败 `{1,15,17,24}`、N7 失败 `{4,15,17,24}`,并集下限 25/28。
- **N13 `qcap4800_allthree`**:Q4800 + 预算×0.5 + critic×8,当前可及的最强组合。N9 与 N10 的失败交集是 `{1,15,24}`,并集下限 **25/28**;若 day 1 和 15 仍只在最差 seed 上越限,下一步应加裕度(预算×0.25)或改用软裕度代价,而**不是**继续加容量。

# 第六轮:27/28,以及第二次撤回一个容量外推(2026-07-30,N11 / N12 / N13)

三个 run 各 1000 updates,按日评估 `--seeds-per-day 3`,判据不变(raw vcost ≤ 0.02 且全部 seed 达标)。

| 变体 | 组成 | train | test | val | **all** | vcost 均值 | day 24 | econ 均值 | 解决的硬日 |
|---|---|---|---|---|---|---|---|---|---|
| N9 | Q4800 | 19/20 | 2/4 | 3/4 | 24/28 | 0.0098 | 0.1378 | 9.961e5 | 4, 23 |
| N10 | Q2400+紧预算+critic×8 | 18/20 | 2/4 | 4/4 | 24/28 | 0.0125 | 0.2922 | 1.391e6 | 17, 23 |
| **N11** | Q9600 | **20/20** | 3/4 | **4/4** | **27/28** | **0.0024** | 0.0592 | 9.390e5 | **1, 4, 15, 17**, 23 |
| **N12** | Q4800+紧预算 | 19/20 | 3/4 | **4/4** | **26/28** | 0.0030 | **0.0439** | 1.065e6 | **1, 15, 17**, 23 |
| **N13** | Q4800+紧预算+critic×8 | **20/20** | 3/4 | **4/4** | **27/28** | 0.0042 | 0.0986 | **8.692e5** | **1, 4, 15, 17**, 23 |

**六个硬日型中的五个(1, 4, 15, 17, 23)已被解决,唯一剩下的是 day 24。**N11 与 N13 都只在 day 24 上失败,train 20/20、validation 4/4。

## 1. 两条不同的路径都到 27/28,便宜的那条更好

N11 靠纯容量(9600 kVA/agent),N13 靠**一半的容量**(4800)加上裕度与 critic 拟合。两者安全日数相同,但:

| | 无功容量 | econ 均值 | 相对冻结基线 |
|---|---|---|---|
| N11 | 9600 kVA | 9.390e5 | 0.248× |
| N13 | **4800 kVA** | **8.692e5** | **0.229×** |

N13 是全系列经济性最优,且容量只有 N11 的一半。**结论:把无功容量当作唯一手段是昂贵且不必要的**;算法侧的裕度与 critic 拟合可以换掉整整一倍的硬件容量。这对论文是比 27/28 本身更有价值的一句话。

## 2. 必须撤回(第二次):day 24 的容量外推

第五轮撤回了第三轮的"day 24 是物理边界",依据是 N9 提供的第三个点显示趋势在**加速**(4.37×/翻倍),并据此预测 9600 kVA 处 day 24 ≈ 0.032、达标需 9,600–19,200 kVA。N11 实测 **0.0592**,比预测高 1.85 倍。完整扫描:

| 无功容量 kVA | 0 | 1200 | 2400 | 4800 | **9600** |
|---|---|---|---|---|---|
| day 24 vcost | 1.4154 | 1.1335 | 0.6015 | 0.1378 | **0.0592** |
| 相邻翻倍降幅 | — | 1.25× | 1.88× | 4.37× | **2.33×** |

**每翻倍降幅是非单调的**(1.25× → 1.88× → 4.37× → 2.33×),在 2400→4800 一步达到峰值后回落。用任一相邻比值外推都不成立:从 0.0592 降到 0.02 还需 2.96×,按观测到的比值区间 1.25×–4.37× 折算是 0.8 到 4.9 个翻倍,即 **16,700 到 290,000 kVA**——一个跨 17 倍的区间,没有任何决策价值。**第五轮"day 24 需要额定的 8–16 倍无功容量"这一量化结论就此撤回。**

**方法论教训(与前两条并列,一起进 limitations)**:第五轮的撤回是正确的(N9 的量级确实推翻了"物理边界"),但我在同一段里用那个新点**又立了一个速率外推**,这一步是错的。**单个新数据点可以推翻一个断言,却不足以确立一条速率**;要给出速率,至少需要看到相邻比值稳定下来,而这里它从未稳定。

更决定性的是下一节:day 24 根本不该用容量来定价。

## 3. day 24 不是容量问题:半个容量 + 裕度打败了双倍容量

**N12(4800 + 预算×0.5)的 day 24 = 0.0439,优于 N11(9600,常规预算)的 0.0592。**一次预算收紧,效果超过一整个容量翻倍。同容量下的对照更干净:

| 变体(容量固定 4800) | day 24 均值 | seed 区间 | 最差/最好 |
|---|---|---|---|
| N9(常规预算) | 0.1378 | — | — |
| **N12(预算×0.5)** | **0.0439**(3.14× 改善) | [0.0184, 0.0577] | 3.1× |
| N13(预算×0.5 + critic×8) | 0.0986 | [0.0740, 0.1129] | 1.5× |
| N11(9600,常规预算) | 0.0592 | [0.0146, 0.1113] | 7.6× |

所以 day 24 的正确读法不是"还差多少 kVA",而是"裕度机制还差多少"。**把 day 24 折算成无功容量需求这个提法本身是错的框架**,这也是上一节那个外推注定失败的根本原因——我在拟合一条不该存在的曲线。

## 4. critic×8 与裕度的张力被复现,而且这次是单变量对照

N12 与 N13 **只差 `critic_epochs`**(1 vs 8),这是本系列第一次拿到这个机制的单变量对照:

| | N12 | N13 | 变化 |
|---|---|---|---|
| 安全日 | 26/28 | **27/28** | +1(得 day 4) |
| econ 均值 | 1.065e6 | **8.692e5** | **−18%** |
| day 24 均值 | **0.0439** | 0.0986 | **恶化 2.25×** |
| day 24 最好 seed | **0.0184(达标)** | 0.0740(不达标) | 失去唯一的达标 seed |

方向与第四轮 N1→N6 完全一致:**critic 变准 → 不再误判不可行 → 把约束余量花在经济性上 → 贴预算收敛 → 在最难的那天失去裕度**。第四轮这个现象体现在把三个容易日推过界(day 2、17、18),这一次容易日全都保住了(train 20/20),代价集中到了唯一的硬日 day 24 上。

值得单独记一笔:**N13 是唯一在 day 24 上三个 seed 全部越限的变体**(区间 [0.0740, 0.1129]),而 N11 和 N12 都有 seed 达标。也就是说 critic×8 把 day 24 从"裕度问题"推回成了"能力问题"。这不是要撤销 critic×8——它换来了 +1 安全日和 −18% 经济成本——而是说明**它必须配更多裕度,而 `cost_budget_scale: 0.5` 对 day 24 已经不够**。

## 5. 剩余失败的性质:除 N13 的 day 24 外,全是"最差 seed"

评估是确定性策略,seed 间差异全部来自环境日内实现噪声。第五轮说"剩余失败均值接近预算",第六轮可以说得更强:

- N11:唯一失败 day 24,区间 **[0.0146, 0.1113]**,最好 seed 已在预算内;
- N12:day 4 区间 **[0.0004, 0.0482]**(最好 seed 近乎为零)、day 24 区间 [0.0184, 0.0577],两天的最好 seed 都达标;
- N13:day 24 区间 [0.0740, 0.1129],**唯一一个没有 seed 达标的剩余失败**。

**在 N11 和 N12 上,没有任何一个剩余失败日是"策略做不到"——每一天都存在一个环境实现使其达标。**策略已经具备能力,缺的是**鲁棒性**。而纯 hinge 代价在越限前梯度恒为零,策略没有任何信号去争取鲁棒性,这正是第四、五轮两次撞上的同一个结构性缺陷。

## 6. 安全与经济同向改善,第六次成立

N13:**27/28 安全日 + econ 8.692e5**,对冻结基线的 10/28 + 3.79e6 是安全日 2.7 倍、经济成本 **0.229 倍**。整个系列(基线 → retry1 → N1/N3 → N4/N5/N6 → N7/N9/N10 → N11/N12/N13)从未出现"安全变好、经济变差"的组合,唯一例外仍是紧预算单独作用时(N3/N4),而它与足够无功容量合并后经济代价被完全抵掉。

## 第六轮结论与第七轮设计

1. **五个硬日型已解决,只剩 day 24**;27/28 由两条路径达成,其中 N13 用一半容量拿到全系列最优经济性。
2. **"day 24 需要额定 8–16 倍无功容量"撤回**;每翻倍降幅非单调,速率外推无效。教训:单点可推翻断言,不足以确立速率。
3. **day 24 不是容量问题**:4800+紧预算(0.0439)优于 9600+常规预算(0.0592)。
4. **critic×8 的代价被单变量对照确认**:换来 +1 安全日与 −18% econ,代价是 day 24 失去全部达标 seed;它需要比 ×0.5 更多的裕度。
5. **剩余失败在 N11/N12 上全是最差-seed 鲁棒性问题**,而纯 hinge 在越限前无梯度。

据此启动第七轮,三个 run 各针对一条上面得出的结论:

- **N14 `qcap9600_tight`(Q9600 + 预算×0.5)**:N11 的容量 + N12 的裕度。N11 的 day 24 最好 seed 已是 0.0146,而紧预算在同容量下把 day 24 均值压 3.14 倍**并把 seed 离散度从 7.6× 收到 3.1×**——正好是把"最好 seed 达标"变成"全部 seed 达标"所需的东西。N11 失败 `{24}`、N12 失败 `{4,24}`,并集下限 27/28(且按第五轮教训读作下限);**这是本系列第一次有理由预测 28/28**。
- **N15 `qcap4800_budget025`(Q4800 + 预算×0.25)**:固定容量,只把裕度再翻一倍,直接回答"裕度单独能不能解决 day 24"。判据:day 24 若从 N12 的 0.0439 进到预算内,则 day 24 与容量无关,4800 kVA 足够;若停在 0.02–0.04,说明单纯缩预算已到收益递减,应转向软裕度。
- **N16 `qcap4800_softmargin`(Q4800 + 训练带 0.96/1.04,常规预算)**:与 N9(Q4800 常规预算,day 24 = 0.1378,24/28)构成**单变量对照**。做这个而不是继续缩预算的理由是机制性的:**缩预算只能给策略已经看得到的代价加权重,而 hinge 在越限前恒为零,那里根本没有代价可加权;内移拐点是唯一能在真实越限之前造出非零梯度的手段。**评估必须加 `--env-override power_flow_vmin_pu=0.95 --env-override power_flow_vmax_pu=1.05` 才可比(该参数已于本轮训练期间加入评估脚本并验证)。诚实记录其confound:内移拐点同时抬高了同一策略的 raw cost,所以它也隐含收紧了有效预算;它与 N15 的区别不在"更严",而在"越限前有无梯度"。

|---|---|---|---|---|---|---|---|---|---|
| N9 | Q4800,常规预算 | 19/20 | 2/4 | 3/4 | 24/28 | 0.0098 | 0.1378 | 9.961e5 | {1,15,17,24} |
| N11 | Q9600 | 20/20 | 3/4 | 4/4 | 27/28 | 0.0024 | 0.0592 | 9.390e5 | {24} |

**N16 达成 28/28,六个硬日型全解决,包括 day 24。**这是本系列第一次没有失败日,也是第一次 test split 满分(test 含 day 24,是全数据集最难的一天)。

而三个 run 里我事前押的那个(N14)输了:预测 28/28,实测 26/28,连"并集下限 27/28"都没保住。下面按预注册的三个问题逐条回答。

## 1. 问题(a):N14 失败,并且"安全日并集是下限"这条启发式第一次被推翻

第六轮写的推理是:N11 失败 `{24}`、N12 失败 `{4,24}`,合并两者的机制应当不低于 27/28,而紧预算在同容量下把 day 24 均值压 3.14 倍并把 seed 离散度从 7.6× 收到 3.1×,正好是把"最好 seed 达标"变成"全部 seed 达标"所需的东西。

实测 **26/28**,失败 `{1, 24}`,而且 day 24 = **0.1829**,比两个父变体都差:

| 变体(day 24) | 无功容量 | 预算 | 均值 | seed 区间 | 违规小时 |
|---|---|---|---|---|---|
| N11 | 9600 | ×1 | 0.0592 | [0.0146, 0.1113] | 16,17,18 |
| N12 | 4800 | ×0.5 | 0.0439 | [0.0184, 0.0577] | 7–11, 16, 17 |
| **N14** | **9600** | **×0.5** | **0.1829** | [0.1381, 0.2555] | 16,17,18,19 |

**这是本系列第一次出现负协同:两个各自有效的机制合并后比任一单独使用更差**,并且 day 24 连一个达标 seed 都没剩(此前只有 N13 如此)。它还把 N11/N12 都已解决的 day 1 推回越限(0.0147,区间 [0.0000, 0.0339],最差 seed 越限)。

**第五轮立下的「安全日并集是下限而非点估计」就此撤回其"下限"部分。**正确的说法只剩:合并机制的结果**无法从单机制的失败集预测**——它可能高于并集(N7/N9 各 24/28,高于我预测的 21–22),也可能低于并集(N14 26/28,低于下限 27/28)。这是本系列**第三条**被自己后续实验推翻的定量断言,和前两条一起进 limitations。

值得记一笔的是失败方向:N14 是全系列 `worst vmin` 最低的变体(0.9403),两个机制叠加后策略反而更贴边。这在下一节会得到解释。

## 2. 问题(b):N15 给出的答案是"反转",不是"收益递减"

预注册的判据是:day 24 若从 N12 的 0.0439 进到预算内,则容量无关;若停在 0.02–0.04,则缩预算已到收益递减。实测是第三种情况——**变差**:

| Q4800 固定,只变预算 | budget_raw | day 24 | 安全日 |
|---|---|---|---|
| N9 ×1 | 0.02 | 0.1378 | 24/28 |
| **N12 ×0.5** | 0.01 | **0.0439** | 26/28 |
| N15 ×0.25 | 0.005 | 0.0735 | 25/28 |

**显式预算收紧存在内部最优,大约在 ×0.5,再收就反转。**沿这条轴能达到的最好 day 24 是 0.0439。这一点在下一节是决定性的:它把"缩预算"这条轴**穷尽**了。

N15 还把 day 1 推到 0.0233(均值本身越限,不再只是最差 seed),这与 N14 的方向一致:预算越紧,容易日和中等日越贴边。

## 3. 问题(c):N16 vs N9 单变量对照——软裕度胜出,且 confound 可以被数据排除

N16 与 N9 只差训练期的电压带(0.96/1.04 vs 0.95/1.05),容量同为 4800,预算同为常规:

| | N9 | N16 | |
|---|---|---|---|
| 安全日 | 24/28 | **28/28** | +4 |
| vcost 均值 | 0.0098 | **0.0000** | |
| day 24 | 0.1378 | **0.0003** | **459×** |
| econ 均值 | 9.961e5 | 1.116e6 | +12% |

第六轮预先记录的 confound 是:内移拐点同时抬高同一策略的 raw cost,因此**隐含**收紧了有效预算,于是 N16 的优势可能只是"更严"而非"越限前有梯度"。**这个 confound 现在可以被数据排除,而不只是记录在案:**

沿"更严"这条轴,本轮已经把它走到穷尽——N9 (×1) → N12 (×0.5) → N15 (×0.25),day 24 走出 0.1378 → 0.0439 → 0.0735,**在 ×0.5 处触底并反转,该轴可达的最好值是 0.0439**。N16 拿到 **0.0003**,比那条轴的最优点还好 **146 倍**,而且它的**标称预算根本没动**(budget_raw = 0.02,与 N9 相同)。如果 N16 的优势只是隐含的预算收紧,它应当落在那条轴上的某一点;它落在轴的最优点之外 146 倍处。**因此起作用的变量不是"约束有多严"。**

(严格性说明:两个旋钮不在同一标度上,所以这是"穷尽已观测的显式区间"的论证,不是代数证明。但显式轴已经出现内部最优并反转,这一点使"N16 只是走到了这条轴更远处"这个解释不成立——那条轴更远处已经实测过了,是 0.0735。)

更直接的证据是**预算占用率**:N16 在自己的(更难的)带上以 60.3% 的预算占用率收敛,是全系列占用率**最高**的之一,即它是被约束得**最松**的:

| | budget_raw | 训练末段 vcost_raw(各自带上) | 占用率 |
|---|---|---|---|
| N11 Q9600 | 0.02 | 0.0032 | 15.9% |
| N15 Q4800+×0.25 | 0.005 | 0.0009 | 17.3% |
| N9 Q4800 | 0.02 | 0.0053 | 26.6% |
| N14 Q9600+×0.5 | 0.01 | 0.0026 | 26.4% |
| N13 Q4800+×0.5+critic8 | 0.01 | 0.0044 | 43.6% |
| N12 Q4800+×0.5 | 0.01 | 0.0057 | 56.8% |
| **N16 Q4800+软裕度** | **0.02** | 0.0121 | **60.3%** |

一个被约束得最松、标称预算最大的变体拿到了唯一的 28/28。**"更严"作为解释变量在两个方向上都不成立。**

## 4. 机制被直接测到了:软裕度真的产生了裕度,而缩预算不产生裕度

这是本轮最有价值的一张表。对每个变体统计 28 天的最差 `vmin`(评估在真实带 0.95/1.05 上):

| 变体 | worst vmin | vmin<0.955 的天数 | vmin<0.96 的天数 | vmin 中位数 |
|---|---|---|---|---|
| N9 Q4800 | 0.9424 | 13 | 17 | 0.9564 |
| N11 Q9600 | 0.9428 | 8 | 14 | 0.9604 |
| N12 Q4800+×0.5 | 0.9456 | **16** | **27** | **0.9538** |
| N13 Q4800+×0.5+critic8 | 0.9439 | 9 | 17 | 0.9596 |
| N14 Q9600+×0.5 | **0.9403** | 10 | 16 | 0.9592 |
| N15 Q4800+×0.25 | 0.9424 | 10 | 15 | 0.9596 |
| **N16 Q4800+软裕度** | **0.9495** | **1** | **9** | **0.9665** |

- **N16 的最差 vmin 0.9495 是全系列最高**,也是唯一高于 0.945 的;
- **裕度不足 0.005 p.u. 的天数:N16 只有 1 天,其他变体 8–16 天**;
- **vmin 中位数 N16 最高**(0.9665,比次高的 N11 高 0.0061)。

而 **N12(预算×0.5)的裕度分布是全系列最差**:16 天不足 0.005 p.u.、27/28 天低于 0.96、中位数 0.9538,**比常规预算的 N9 还差**。也就是说:

> **收紧预算改善了硬日的代价,同时让其余所有天更贴近边界。**

这正是纯 hinge 的盲区在数据上的样子:hinge 在 v ≥ 0.95 时恒为零,**它不区分 v=0.951 与 v=0.970**。缩预算只是给"已经越限的那部分"加权重,策略因此没有任何理由在不越限的日子保住裕度,反而可以把裕度换成经济性。内移拐点则在 v < 0.96 处处处给出非零梯度,于是整条 vmin 分布被抬起来。**第四、五、六轮三次从不同方向撞上的"纯 hinge 越限前无梯度"这个结构性缺陷,在第七轮被直接修掉,并且修掉它的收益正是那三轮各自缺的东西。**

一个附带的细节印证了这一点:**N16 在 day 24 唯一残留的越限小时是早上 8 点**(vmin 0.9495,raw cost 0.0003),而其他每一个变体在 day 24 违规的都是晚峰 16–19 点。day 24 的结构性难点——晚峰压降——被完全解决,剩下的 0.0003 是一个清晨小时擦线。

## 5. 代价:经济性回退,以及它为什么大概可以被拿回来

N16 的 econ 1.116e6 是冻结基线的 0.294 倍,但比全系列最优的 N13(8.692e5)高 **28%**。软裕度让策略在 27 天里都多留了 0.005–0.013 p.u. 的电压裕度,这些裕度是花钱买的,回退是预期之内的。

它大概能被拿回来,理由是第六轮的机制结论:`critic_epochs=8` 两次带来 −18% 的经济成本,其失效模式是"贴预算收敛后在最难那天失去裕度"(第六轮 N13 是唯一 day 24 三个 seed 全越限的变体),而**软裕度恰好是一个不依赖预算的裕度来源**。这构成第八轮的 N19。

## 6. 安全与经济同向改善,第七次成立(但这一次要加限定)

对冻结基线(10/28,econ 3.79e6),N16 是安全日 2.8 倍、经济成本 0.294 倍。序列整体从未出现"安全变好、经济变差"。但第七轮出现了系列内部的首次明确权衡:**N16 相对 N13 是 +1 安全日 / +28% 经济成本**。诚实的表述应当是:相对基线安全与经济始终同向,但在已经接近饱和的高安全区间,继续提升安全开始需要付经济代价。

## 第七轮结论与第八轮设计

1. **28/28 达成**(N16:Q4800 + 训练带 0.96/1.04 + 常规预算),六个硬日型全解决,train 20/20、test 4/4、val 4/4,评估在真实带上完成且已核对 `eval_env_overrides`。
2. **达成它的机制是"越限前存在梯度",不是容量也不是预算严格性。**显式预算轴已被穷尽并显示内部最优(×0.5)与反转(×0.25),其最优点仍比 N16 差 146 倍;而 N16 的标称预算未动、预算占用率全系列最高(60.3%),即被约束得最松。
3. **机制被直接测量证实**:软裕度把 `vmin` 分布整体抬高(不足 0.005 p.u. 裕度的天数 8–16 → 1,中位数 0.9538–0.9604 → 0.9665),而**缩预算不产生裕度、反而恶化它**(N12 的裕度分布全系列最差,比常规预算的 N9 还差)。这是"纯 hinge 在越限前不区分 0.951 与 0.970"这一盲区的直接观测。
4. **第三条定量断言被撤回**:「安全日并集是下限」不成立。N14(两个有效机制合并)得 26/28,低于并集下限 27/28,且 day 24 = 0.1829 差于两个父变体——首次负协同。合并机制的结果无法从单机制失败集预测,两个方向都可能。
5. **代价是经济性相对系列最优回退 28%**,并出现系列内首次明确的安全-经济权衡。

据此启动第八轮,三个 run 各答一个必须先答的问题:

- **N17 `qcap4800_softmargin_seed31`(N16 + 训练种子 31,其余逐键相同)**:28/28 目前建立在**单个训练种子**上,这是审稿人第一刀。本轮最高价值的 run,刻意不引入任何新机制。判据:若 ≥27/28 则 28/28 可复现;若掉到 24–25/28,则第 2 条结论必须降级为"软裕度显著改善但存在种子方差"。
- **N18 `qcap2400_softmargin`(软裕度 + 容量砍半到 2400)**:同容量的既有点是 N5(常规带)20/28、N7(2400+预算×0.5)24/28。若软裕度在 2400 上守住 ≥26/28,则**越限前的梯度可以替代整整一倍硬件容量**,这是本系列 headline 的最强形式;若跌回 20–24/28,则软裕度是"充足容量的放大器"而非"容量的替代品"——同样是可发表且诚实的边界。
- **N19 `qcap4800_softmargin_criticfit`(软裕度 + `critic_epochs=8`,与 N16 单变量对照)**:直接冲第 5 条的经济性回退。机制预期见上;判据:若保住 ≥27/28 且 econ ≤ 9e5,则"28/28 且全系列最优经济性"同时达成,第 6 条的权衡叙述可以取消。

## 附录 A(第七轮离线):软裕度是否也改善了成本 critic 的拟合——部分阳性,且大部分证据带 confound

第四轮的结论是成本 critic 欠拟合(样本外 RMSE 与代价同量级),第七轮的结论是纯 hinge 越限前无梯度。两者合起来给出一个此前没测过的预言:**hinge 的平坦区不仅让策略梯度消失,也让大部分样本对"代价函数长什么样"不提供信息,所以内移拐点应当让 critic 的相对拟合误差下降。**

N9 与 N16 是干净的单变量对(容量同为 4800、标称预算同为 raw 0.02,只差训练带),用 `analyze_softmargin_critic.py`(纯 CPU,从 metrics.jsonl 算)比较 `sqrt(cost_critic_loss) / |cost_before|`:

| | 窗口 | critic RMSE | \|cost\| | RMSE/\|cost\| |
|---|---|---|---|---|
| N9(带 0.95) | u200–400 | 0.5610 | 0.2785 | 2.015 |
| N9(带 0.95) | u800–1000 | 0.6397 | 0.3222 | 1.986 |
| N16(带 0.96) | u200–400 | 1.0289 | 0.5464 | 1.883 |
| N16(带 0.96) | u800–1000 | 0.9058 | 0.5854 | **1.547** |

**必须先说清 confound**:内移拐点必然抬高 raw cost 的量级,而 raw cost 正是这个比值的分母。若 RMSE 存在一个加性下限,分母变大会**自动**改善比值。因此**末段的横向差异(1.547 vs 1.986)不能作为证据** ——这个检验的设计无法把"critic 拟合更好"与"分母更大"分开。

**唯一不带这个 confound 的是各自 run 内部的趋势**:窗口之间两个 run 的 \|cost\| 变化幅度相当(N9 +15.7%,N16 +7.1%),但比值走向相反——

- **N16:1.883 → 1.547(−17.8%),持续改善;**
- **N9:2.015 → 1.986(−1.4%),基本平台。**

也就是说,在真实带上训练的 critic 早早停止进步,而在内移带上训练的 critic 一直在变准。这与"平坦区里的样本不携带关于代价函数的信息"一致,并且不能由分母解释。

另外两点诚实交代:

1. **"非零代价样本占比"这个代理指标在 update 粒度上饱和,没有信息量**(N9 0.995、N16 1.000):一个 update 聚合了 16 env × 24 step × 4 agent,几乎总有某处越限。要真正测这条机制需要 per-step 的代价分布,现有 metrics 里没有,本轮不补。
2. **跨变体的相关(\|cost\| 越小、相对误差越大:N15 0.0357→4.560、N11 0.1050→3.550、N9 0.3222→1.986、N16 0.5854→1.547)看着很支持这条机制,但它就是上面那个分母效应**——绝对 RMSE 其实是随 \|cost\| **一起增大**的(0.163 → 0.373 → 0.640 → 0.906)。**这条相关不构成证据,不要写进论文正文。**

结论:软裕度改善 critic 拟合这条**得到了一个方向正确、且不可由分母解释的证据(训练内趋势),但强度弱于第 4 节那组 vmin 分布的直接测量**。第七轮的主张仍应建立在 vmin 分布上;这一条作为辅助机制线索保留,若要坐实需要 per-step 代价分布的插桩。

## 1. 问题(a):28/28 有种子敏感性,但软裕度本身不敏感

N17 与 N16 只差训练种子,得 **27/28**(唯一失败 day 24,0.0506)。所以预注册判据里的"≥27/28 则可复现"成立,但"28/28"这个具体数字确实依赖种子。正确的表述分两层:

- **软裕度的效应本身很稳**:同容量 4800 上,两个种子分别 28/28 与 27/28,而硬 hinge 在同容量上是 N9 24/28、N12 26/28、N15 25/28、N13 27/28。两个软裕度种子都不低于硬 hinge 的最好结果。
- **"零失败日"是边缘事件**:day 24 在软裕度下的四个取值是 0.0003 / 0.0506 / 0.1634 / 0.0074,预算是 0.02,即它就在判据线附近来回。**报告 headline 应写「软裕度稳定达到 27–28/28,并两次达成 28/28」,不写「软裕度达成 28/28」。**

## 2. 问题(b):容量替代成立,而且比预注册的判据更强

预注册判据是"N18 在 2400 上守住 ≥26/28 则梯度可替代一倍硬件容量"。实测 **27/28**。同容量的三点对照:

| 无功容量 2400 固定 | 训练带 | 预算 | 安全日 | day 24 | vmin<0.955 的天数 |
|---|---|---|---|---|---|
| N5 | 0.95/1.05 | ×1 | 20/28 | 0.6015 | 17 |
| N7 | 0.95/1.05 | ×0.5 | 24/28 | 0.4918 | 18 |
| **N18** | **0.96/1.04** | ×1 | **27/28** | 0.1634 | **7** |

而跨容量看:**N18(2400 kVA)的 27/28 与 N11(9600 kVA,硬 hinge)的 27/28 相等**,裕度分布还更好(vmin<0.955 的天数 7 vs 8)。

> **在这个环境里,把 hinge 拐点从 0.95 内移到 0.96,换掉了四倍的无功容量。**

这是本系列 headline 的最强形式,也是最有工程意义的一句话:它把"要装多少无功补偿"变成了"要怎么定义代价"。代价是经济性——N18 的 econ 1.835e6 是软裕度四个 run 里最高的,少一半容量要用更贵的调度去补,方向合理。

## 3. 问题(c):N19 达成第二个 28/28 并满足预注册的经济性判据,但见第 4 节

预注册判据是"≥27/28 且 econ ≤ 9e5"。N19(软裕度 + `critic_epochs=8`)得 **28/28,econ 8.351e5**,两项都满足,且 8.351e5 是**全系列最低**(此前最低是 N13 的 8.692e5)。day 24 = 0.0074,是软裕度四个 run 里第二好。

机制与预期一致:第六轮的结论是 critic×8 的失效模式为"贴预算收敛后在最难那天失去裕度",而软裕度提供的是**不依赖预算的裕度**,两者因此互补而非冲突——N13(critic×8 + 预算×0.5)day 24 = 0.0986 且三个 seed 全越限,N19(critic×8 + 软裕度)day 24 = 0.0074 且全部达标。

**但第七轮第 6 条那句"出现系列内首次明确的安全-经济权衡"不能就此简单取消,因为下一节表明它当初就不该被断言。**

## 4. 必须回头修正的方法论:单种子之间的经济性比较一直在噪声里

N16 与 N17 是同一份 config、只换种子,这是本系列**第一次**拿到种子方差的估计:

**同一配置换个种子,经济成本差 28%。**而此前若干轮里被当作结论写下的经济性差异,量级与此相当或更小:

| 出处 | 断言 | 实际差 | 是否可与 28% 的种子噪声区分 |
|---|---|---|---|
| 第六轮 | N13 比 N12 经济性好 18% | −18% | **不能** |

所以要明确修正:**所有基于单种子 run 之间、幅度低于约 30% 的经济性比较都不成立,包括我自己在第四、六、七、八轮写下的那几条。**安全日数受影响较小(种子差 1 天),但"±1 安全日"也应据此读作噪声,这同时意味着**第七轮 N14 的 26/28 与并集下限 27/28 之间那 1 天差距本身在噪声内**——第七轮撤回「并集是下限」的**理由需要弱化**:真正站得住的证据不是那 1 天,而是 N14 的 day 24 = 0.1829 差于两个父变体的 0.0592/0.0439(差 3–4 倍,远超种子噪声),以及它把 day 1 推回越限。撤回本身仍然成立,但应以 day 24 的量级为据。

这是本系列**第四条**需要自我修正的东西,而且它与前三条性质不同:前三条是把一个断言外推过头,这一条是**从头就没有做过误差估计**。第九轮因此不加任何新机制,只补种子。

## 第八轮结论与第九轮设计

1. **软裕度稳定给出 27–28/28**(四个 run:28/27/27/28),而软裕度之前的 18 个 run 里最好是 27/28 且仅两例。四个 run 都把硬日型 1/4/15/17/23 压到恰好 0.0000,只有 day 24 在判据线附近浮动。**headline 应写「27–28/28」而非「28/28」。**
2. **拐点内移 0.01 p.u. 换掉四倍无功容量**:N18(2400,软)27/28 = N11(9600,硬)27/28,裕度分布还更好;同容量对照 N5 20/28、N7 24/28 → N18 27/28。
3. **N19(软裕度 + critic×8)达成第二个 28/28,econ 8.351e5 为全系列最低**,机制上与第六轮"critic×8 缺的是不依赖预算的裕度"吻合(N13 day 24 三 seed 全越限 → N19 全部达标)。
4. **方法论自我修正(第四条)**:N16/N17 同配置换种子的 econ 差 28%,**因此第四、六、七、八轮里所有幅度 <30% 的单种子经济性比较都不成立**;±1 安全日同样应读作噪声,第七轮撤回「并集是下限」的依据应改为 day 24 的 3–4 倍量级差而非那 1 天。此前从未做过误差估计,这是根子上的疏漏。
5. **最稳健的机制证据是 vmin 分布**:两个容量档的同容量对照里,软裕度都把裕度不足 0.005 p.u. 的天数压到硬 hinge 的三分之一以下(17–18→7,9–16→1–3),四个软裕度 run 与十个硬 hinge run **区间完全不重叠**。建议以此作为论文主结论。

第九轮**不加任何新机制,只补种子**,直接修第 4 条:

## 1. 问题(a):旗舰配置是 27–28/28,N19 的「全系列最低 econ」不成立

三个种子给出 28 / 27 / 28,**第八轮第 1 条要求把 headline 写成「27–28/28」而不是「28/28」,在 n=3 上得到确认**,不是 n=2 的偶然。

## 2. 问题(b):容量替代复现成功,但代价被第八轮低估了一个量级

N22(Q2400 软裕度,seed 31)得 **27/28**,与 N18 **完全一致**;两个种子的 worst vmin 中位数 0.9613 / 0.9611 几乎重合。第八轮第 2 条「拐点内移 0.01 p.u. 换掉四倍无功容量」**在两个种子上站得住**。

但第八轮只说代价是「经济性方向合理」,没有量化,也没有对照噪声。现在可以:

| 对照 | econ | 相对 N11 | 是否超出种子噪声(见第 3 节,门槛 ~45%) |
|---|---|---|---|
| N11 Q9600 硬 hinge,27/28 | 9.390e5 | — | — |
| C 组 Q2400 软裕度,27/28 | 2.110e6 | **2.25×** | **是,远超** |
| A 组 Q4800 软裕度+critic×8,27–28/28 | 8.673e5 | 0.92× | 否,不可分辨 |

所以正确的工程表述分两段,而不是一句:

> - **9600 → 4800 kVA:软裕度让容量减半且安全性不降(27–28/28 对 27/28),运行成本无可测差异(0.92×,在噪声内)。这一半容量是白拿的。**
> - **4800 → 2400 kVA:安全性仍守住 27/28,但运行成本涨到 2.25 倍。这一档是把资本开支换成运行开支,不是白拿。**

第八轮那句「换掉四倍容量」单独拿出来会让人以为四倍都是免费的,必须带上 2.25× 这个数一起写。

## 3. 问题(c):种子方差的合并估计,门槛应从 30% 提到 45%——第八轮的自我修正本身还不够狠

三组的组内相对偏差可以合并(dof=4),这比第八轮那个 n=2 的单点估计可靠得多:

```
pooled CV[econ ] = 16.2%   (dof=4)
单个 run 的 econ 1σ            : 16.2%
两个单种子 run 之差的 1σ        : 22.9%
95% 门槛(z=1.96)              : 45%
95% 门槛(t(4)=2.776)          : 64%
```

第八轮定的门槛是 30%,来自 n=2 的一次极差。**用合并估计,门槛至少是 45%。**这意味着第八轮那张修正表还漏了一条:

| 出处 | 断言 | 实际差 | 第八轮判定(门槛 30%) | 本轮判定(门槛 45%) |
|---|---|---|---|---|
| 第六轮 | N13 比 N12 好 18% | −18% | 不成立 | 不成立 |
| 第七轮 | N16 比 N13 回退 28% | +28% | 不成立 | 不成立 |
| 第八轮 | N19 比 N16 好 25% | −25% | 不成立 | 不成立 |
| 第四轮 | **critic 变准后 econ 改善 38%** | −38% | 「勉强,不宜当定论」 | **明确不成立** |

**这是第五条自我修正,而且它修的是第四条本身:我在第八轮做误差估计时用了 n=2,得到的门槛偏松,于是把第四轮那条 38% 留了个「勉强」的活口;n=3 合并之后它也倒了。**教训不是「要做误差估计」——第八轮已经做了——而是**用 n=2 估方差本身就不够,极差在小样本上严重低估离散度**。

安全日数的合并 1σ 是 **0.54 天**,所以「±1 安全日是噪声」这个第八轮的判断成立(1 天 ≈ 1.9σ,勉强在边缘),继续沿用。

## 4. 顺带修正第八轮第 5 条:推荐的统计量对,但推荐的理由不对

第八轮建议以「vmin<0.955 的天数」作为论文主结论,理由是软/硬两组区间不重叠。本轮先发现一个反直觉的数:**这个计数统计量的组内 CV 是 45.3%,比 econ 的 16.2% 还高**——它本身一点也不「稳」。区间不重叠不等于统计量稳健,两者是不同的事。

正确的判据是**效应量 / 种子噪声**。对七个硬 hinge run 与七个软裕度 run 逐个统计量算(`/tmp/stat_choice.py`):

| 统计量 | 硬组均值 | 软组均值 | 效应 | 种子 1σ | **效应/σ** | 两组区间 |
|---|---|---|---|---|---|---|
| vmin<0.955 的天数 | 13.00 | 2.86 | −10.1 | 1.58 | **6.4×** | **不重叠** |
| worst vmin 中位数 | 0.9562 | 0.9636 | +0.0074 p.u. | 0.0014 p.u. | **5.4×** | **不重叠** |
| 安全日数 | 24.86 | 27.43 | +2.57 | 0.54 | 4.8× | 重叠(硬组最好 27 = 软组最差 27) |
| vcost 均值 | 0.0113 | 0.0034 | −0.0079 | 0.0064 | 1.2× | 重叠 |
| econ 均值 | 1.053e6 | 1.338e6 | +2.85e5 | 2.4e5 | 1.2× | 重叠 |
| **最差单日 vmin** | 0.9412 | 0.9449 | +0.0037 p.u. | 0.0060 p.u. | **0.6×** | 重叠 |

三个可直接用于论文的读数:

1. **第八轮的推荐结论正确,但要换理由**:CV 高是因为计数在 2 附近,分母小;真正支撑它的是 6.4× 的效应/噪声比,是全部候选统计量里最高的。
2. **「最差单日 vmin」是个陷阱**:它是电压安全文献里最常报的量,而在这里它的噪声比效应还大(0.6×)。只看这个数会得出「软裕度没有作用」的相反结论。同理,**vcost 均值(1.2×)也不行**,它被 day 24 的重尾主导。**软裕度的效应只有在分布统计量上才看得见,这本身是一个值得写进论文的方法论发现。**
3. **安全日数会饱和**:软组三个种子里有四个 run 顶到 28,天花板压缩了效应,所以它的 4.8× 是被低估的下界——但它同时与硬组在 27 处相接,不能作为主结论。

## 5. day 24 的代价与整体裕度几乎解耦,进一步支持第 4 节

A 组三个种子的 day 24 分别是 0.0074 / **0.4246** / 0.0000。N20 的 0.4246 是全部七个软裕度 run 里最差的(比 Q2400 的 N18 0.1634 还差一倍多),**但 N20 的 vmin<0.955 天数是 2(与同组另外两个完全相同),worst vmin 中位数 0.9661 反而是全组最好**,安全日仍有 27/28。

也就是说:**单日 hinge 代价与整体裕度分布在种子间几乎不相关。**一个 run 可以在 27 天上把裕度做得比谁都好,同时在 day 24 上崩掉。这解释了第 4 节里 vcost 均值只有 1.2× 的原因,也说明此前若干轮把 day 24 的数值当作变体优劣主要依据(第五、六、七轮都这么做过)是**在读一个重尾单点**。day 24 仍可作为「最难日是否被解决」的定性标记,不应再用它的具体数值排序变体。

连同已有的 0.95(硬 hinge,七个 run)与 0.96(三个种子),扫完可得五点剂量-反应曲线。判据按第 4 节改用 **vmin<0.955 天数与 worst vmin 中位数**,econ 差异一律对照 45% 门槛,单种子结果不做低于该门槛的排序。

2. **经济代价的归属要改写**。第 4 节按合并分组得出「econ 效应 1.2×,不可分辨」,这个说法掩盖了
   一个真实的分档差异:
   - **4800 档:效应/σ = 0.2×,软裕度的经济代价在噪声里完全测不出来。**6–7σ 的裕度改善是白拿的。

   合起来就是一句有物理含义的话:**容量够时,裕度由无功出力免费提供;容量不够时,裕度只能靠更贵的
   有功调度去买。**这正是第 2 节「9600→4800 免费、4800→2400 要付 2.25 倍」的同一件事在同容量对照下的

方法论上这是第九轮内部的一次自查:第 4 节的分组比较**结论方向没错,但证据链有混杂**,而混杂的代价
恰好落在最需要小心的那个量(经济性)上——按合并分组会得出「软裕度不要钱」这个在 2400 档明确为假的
结论。**分组对照必须在唯一变量上对齐,哪怕被比较的两组各自内部已经有重复。**

## 第十轮:软裕度拐点位置扫描(N23/N24/N25)——拐点是可标定的裕度旋钮,且在 Q4800 档不要钱

(位移的一半)、N24 = 0.97/1.03、N25 = 0.98/1.02;评估一律恢复真带 0.95/1.05
(三份 JSON 的 `eval_env_overrides` 已逐个核对为 `{0.95, 1.05}`)。加上已有的 0.95 硬 hinge
(N9/N12/N13)和 0.96(N19/N20/N21),得到五点剂量-反应曲线。

本轮中途 AutoDL 实例被停(约 12:35–14:36),三个 run 分别从 update 800/800/750 的 checkpoint
续跑至 1000,未重开输出目录。

### 1. 五点剂量-反应:中位裕度几乎 1:1 跟随拐点

| 拐点 | run | 安全日 | d<0.955 | worst vmin | q1 vmin | **med vmin** | econ |
|---|---|---|---|---|---|---|---|
| 0.950(硬 hinge) | N9/N12/N13 (n=3) | 24–27 | 9–16 | 0.9424–0.9456 | 0.9495–0.9519 | 0.9537–0.9590 | 9.769e5 |

| **0.970** | **N24** | **28** | **0** | 0.9596 | 0.9671 | **0.9744** | 7.542e5 |
| **0.980** | **N25** | **28** | **0** | 0.9563 | 0.9759 | **0.9825** | 7.610e5 |

——想要多少裕度,把拐点设在目标值下方约 0.004 即可,不需要试错。

这条标定关系顺带解释了 **N23 为什么白做**(预注册问题 (b) 的答案是**否**):拐点只内移
0.005,分布整体也只平移 0.005,而分布自身的四分位距是 0.014,是位移的近 3 倍——一半的位移
根本淹没在分布宽度里。N23 的 25/28、d<0.955=10、med 0.9586 三项全部落在硬 hinge 的区间内
(24–27、9–16、0.9537–0.9590),**与不加软裕度不可分辨**。软裕度不是「加一点有一点效果」,
要跨过分布宽度才起作用。

### 2. 经济代价:整段拐点范围内都测不出来,点估计甚至反向

五点的 econ 依次为 9.769e5 → 9.241e5 → 8.673e5 → 7.542e5 → 7.610e5,**随拐点内移单调下降**
(0.97 到 0.98 持平)。按第九轮定下的门槛,十组两两比较全部低于 45%,最大的一组
0.970/0.950 = 0.77×(−23%)也不到门槛的一半,**因此逐对都不作结论**。

但可以作一条比逐对比较更强的陈述:**在 Q4800 档,把训练带从 0.95 一路收到 0.98、换来
med vmin +0.029 p.u. 和 d<0.955 从 9–16 天降到 0 天,却在五个点上都测不到任何经济代价,
而且点估计的方向与「裕度要花钱」的先验相反。**这把附录 B 的结论从「0.96 这一个点上免费」
扩展成「整段范围内免费」,也给附录 B 的物理解释划定了边界:4800 kvar 的无功容量足以免费
买下 0.03 p.u. 的裕度,free lunch 在 0.98 处仍未结束。

因此预注册问题 (b) 的后半段——「软裕度的经济代价能压到多低、Q2400 的 2.25× 能否改善」——
**问题本身在 Q4800 档不成立:没有可测的经济代价可压。**Q2400 那 +57% 的溢价只能归给容量,
不能靠回调拐点消掉。**但必须注明这是从 4800 档外推:本轮没有在 Q2400 上扫拐点**,而附录 B
已经证明 2400 与 4800 两档的经济学是不同的,所以这条外推恰恰是最该被下一轮检验的。

### 3. 有没有反转?没有,但 0.98 在可训练性上出现了真实代价

预注册问题 (c) 要求按**完整轨迹**判断,不是按快照。三个 run 的 mode 混合与 econ 轨迹:

| 窗口 | N23 (0.955) | N24 (0.97) | N25 (0.98) |
|---|---|---|---|
| u0–100 | cost 0.80,vcost 0.695 | cost 1.00,vcost 2.688 | cost 1.00,vcost 5.814 |
| u100–200 | rewa 0.86,vcost 0.005 | cost 0.66,vcost 0.053 | **cost 1.00**,vcost 1.129 |
| u200–300 | rewa 0.81 | rewa 0.60 | **cost 0.99**,vcost 0.195 |
| u300–400 | rewa 0.85 | rewa 0.55 | cost 0.61 / rewa 0.28 |
| u900–1000 | rewa 0.76,cost 0.11 | rewa 0.70,cost 0.14 | **cost 0.53 / rewa 0.28** |
| 末段 vcost_raw | 0.0096 | 0.0118 | **0.0285** |

安全性上**没有反转**:0.97 与 0.98 都是 28/28、d<0.955 = 0。但 N25 付出的是**样本效率**:
它在初始不可行区里整整耗掉 300 个 update 才第一次进入 reward 分支(N23 用 100、N24 用 200),
并且到收敛都还有 53% 的 update 在 cost 分支,末段训练 vcost 是 N24 的 2–3 倍。**拐点 0.98
已经贴近可训练性的边界**:1000 个 update 仍能收敛,但裕量明显变薄。

**这里要记一次自我更正(全项目第六次)。**本轮开跑 15 分钟时我写过一句判断:N25「训练带过紧
把经济目标完全挤掉,与第七轮预算×0.25 同型」。完整轨迹显示这是错的,而且错的方式值得记:
u≈170 时 N25 的 econ 是 5.36e6,不是被压低而是**高**——它当时根本还没开始优化任何东西,只是
停在初始不可行区。**一个早期饱和在 cost 分支的 mode 分布,与一个永久性的经济挤压,在同一个
快照上完全无法区分;区分它们的是导数,不是水平值。**第七轮预算×0.25 那次 econ 是从高位被压
下来并停住,本轮是从未离开过起点——两者在单张快照上同形。凡是用 mode 分布判断「训练失败」的
结论,必须给出至少两个时间点。

### 4. 「最差单日 vmin」再次给出相反的排序

第九轮算出「最差单日 vmin」的效应/噪声只有 0.6×,建议禁用。本轮独立复现了这个失效:

- N25(拐点 0.98)的 worst vmin = **0.9563**,**低于** N24(拐点 0.97)的 0.9596,尽管 N25 的
  中位数高出 0.008、q1 高出 0.009。
- 0.96 组的 N20 worst = **0.9368**,比硬 hinge 的 N12(0.9456)还差,而它的 med(0.9661)是
  全组最好。

也就是说,**若按电压安全文献里最常报告的「最差单日 vmin」排序,0.97 会被判优于 0.98、硬
hinge 会被判优于软裕度**——后者与全部其余证据相反。第九轮的禁用建议在本轮得到独立确认。

另外要澄清一个容易混的点:**安全日判据是积分量(`raw_voltage_cost ≤ 0.02`),不是 vmin 下限**。
N19 的 worst vmin 是 0.9477(低于 0.95)却仍是 28/28,因为那次跌落太短,积分代价未超阈。所以
不能由「worst vmin ≥ 0.95」推安全日数,反之亦然。

### 5. 最优拐点:0.97

按裕度分布统计量取,0.97 与 0.98 在 d<0.955(都是 0)和安全日(都是 28/28)上已经饱和,
需要用未饱和的量来分:0.98 的 med 高 0.008、q1 高 0.009,但 worst 反而低 0.003;而它多花了
300 个 update 停在不可行区、末段训练 vcost 高 2–3 倍。**在 28 天测试集上 0.98 买不到任何可测
的安全收益,却明确更难训练,因此推荐拐点 0.97。**如果未来的日集包含比本集更极端的日型,
0.98 的额外中位裕度才可能兑现——这是一个可检验的推论,不是本轮的结论。

### 6. 一个未修的可复现性缺口(记录,不修)

**训练带没有写进任何 run 产物。**已核对:`metrics.jsonl` 的 39 个键里电压相关的只有
`daily_voltage_cost{,_normalized,_raw}`;run summary json 只有
`['deterministic_rollout','dimensions','exploratory','metrics','resumed_from_update','target_updates','variant']`;
checkpoint sidecar 只有四个键。**本轮三个 run 的区别只能从 launcher 的 spec 反查**,产物本身
无法区分。

**故意不修**:trainer config 的 sha256 指纹覆盖整个 config,增加任何键都会让全部既有 checkpoint
的指纹失配、无法续跑——本轮刚刚靠续跑从实例中断里恢复,这个代价是实打实的。建议的修法是把
band 写进 run summary json(不属于 trainer config,不进指纹),留给下一次需要改 config 的时机
一并做。在此之前,**launcher spec 是训练带的唯一权威记录,不能删改历史 spec**。

# 第十四轮:氢价单位改正(1000 元/kg → 30 元/kg)

## 起因

第十三轮 rollout 暴露:`terminal_h2_value_yuan_per_kwh = 0.0` 不是「不计终端价值」,
而是在 `_terminal_asset_values()` 里回落到 `lambda_h2_buy = 30.0`。该键单位是

后果:期末在罐氢的信用(−573,613 元/日)超过经济成本本身(535,612 元/日),

这是一个真实的协同失效,不是估值假象。可能成因(未验证):

于是策略学会了「按热负荷时序制氢」而不是「按能量可得性制氢」。

## 结论

1. 氢价单位确实是错的,改正后目标函数恢复有界、MACPO 收敛、安全裕度提升、
   甩卖停止。**改价本身是正确且必要的**。
2. 但改价**不能**解释电解槽平剖面。平剖面的原因是电解槽跑在免费的可再生余量上,
   电价对它无意义 —— 主判据被自己的数据推翻。
3. 改价暴露了两个此前被掩盖的问题:内部 P2P 市场被便宜外购挤出;
   A0 的 2000 kW 电解槽在光伏高峰闲置,浪费 71% 的自有余量。
4. 待验证:seed 31/32 复现;给 PV/风电加(带噪声的)前瞻观测,检验 A0 的反相剖面
   是否源于观测缺失。

## 假设

第十四轮发现 A0 的电解槽与自身可再生余量**反相**:h9–h13 余量 2,466–4,368 kW 时

而热负荷有 10 小时**完美**前瞻(`_supply_intent_facts`)。策略可能因此学会了

## 环境改动(严格增量)

`envs/microgrid/microgrid_env.py` 新增 `_renewable_forecast_facts()`,由三个键控制,
**默认关闭**,因此不出现在任何已有 variant 的 config 里,
所有历史 checkpoint 的 fingerprint 不变(已实测 h2kg_3000 / h2kwh_ctrl3000 /
n24_ext3000 三个 checkpoint 均能正常加载)。

| 键 | 值 |
|---|---|
| `renewable_forecast_enable` | True |
| `renewable_forecast_horizons` | [2, 4, 6] |
| `renewable_forecast_noise_std` | 0.15 |

每个 horizon H 给 2 维(共 6 维,obs_dim 32 → 38):未来 `t+1..t+H` 小时内
自身 PV+WT **超出**自身电负荷的能量、以及**不足**的能量,均按
`(pv_cap+wt_cap)*dt*H` 归一并裁剪到 [0,1]。

前瞻是**有噪的**:乘性误差只加在发电上(负荷可预测性高得多),
标准差 `0.15*sqrt(H)`,所以 6 小时视野明显比 2 小时差。这与热负荷那个
**完美**前瞻形成对照 —— 后者本身就是环境的一个不真实之处。

实测:对照臂观测与新臂去掉这 6 维后**逐位相同**;新增 6 维无饱和
(裁到 1.0 的比例 0%);噪声引入的平均绝对偏差随 H 递增 0.056 / 0.060 / 0.099;
同 seed 完全可复现。

## 预注册判据(开跑前写定)
